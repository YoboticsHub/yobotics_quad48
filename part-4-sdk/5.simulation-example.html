4.5 SDK Simulation Example¶

Purpose¶

This section explains how to control MuJoCo simulation with the SDK. It is a good first verification step for high-level secondary development.

Prerequisites¶

  • MuJoCo simulation can start.
  • The SDK has been built.
  • SDK, simulator, and controller use the same LCM URL.

Steps¶

1. Start Simulation in Terminal 1¶

# If MuJoCo is installed in a Conda environment, switch from base to that environment first
conda env list
conda activate robot_controller

bash scripts/start_mujoco.sh --config config_sim.yaml

2. Monitor LCM in Terminal 2¶

bash scripts/monitor_lcm.sh --no-gui

# If LCM is installed in a Conda environment, switch from base to that environment first
conda env list
conda activate robot_controller

3. Run SDK Motion Control in Terminal 3¶

cd yobotics_sdk/build
./yobot_sport_client

4. Run SDK State Reading in Terminal 4¶

cd yobotics_sdk/build
./yobot_robot_state_client

Success Criteria¶

  • The robot in MuJoCo Viewer responds to SDK commands, for example moving from prone/damping to standing and walking.
  • monitor_lcm.sh shows QUAD_ROBOT_CONTROL and QUAD_ROBOT_STATE.
  • State-reading output changes with control commands.

Troubleshooting¶

Symptom Action
SDK commands have no response Confirm that the controller is in a mode that accepts high-level commands
State reading is empty Confirm that LCM URL and state channel match
Simulation falls Reduce velocity commands and check model, PD parameters, and action limits

Safety Note¶

Simulation does not damage hardware, but abnormal simulation motion usually indicates a configuration or model problem. Do not skip the problem and move directly to hardware.
