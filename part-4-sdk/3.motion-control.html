4.3 SDK Motion Control Workflow¶

Purpose¶

This section explains how to send high-level motion-control commands through the SDK.

Prerequisites¶

  • The controller is running in simulation or hardware.
  • The SDK has been built.
  • SDK and controller use the same LCM URL.
  • The robot is in a mode that accepts high-level control, such as gamepad->device_type: hybrid or lcm.

Example Program¶

Motion-control example source:

yobotics_sdk/example/sport_client.cpp

Built program:

yobotics_sdk/build/yobot_sport_client

Run¶

cd yobotics_sdk/build
./yobot_sport_client

Runtime Output¶

Keyboard control started:
1: RECOVERY_STAND | 2: STAND_DOWN | 3: DAMP | 4: RL_WALK | 5: DEVELOPMENT
Move keys: arrow keys
Lateral movement: H/J
QAZ adjust body height: q increase, a decrease, z reset
WSX adjust roll: w increase, s decrease, x reset
EDC adjust pitch: e increase, d decrease, c reset
V: exit program
Mode switch -> 3

To specify an LCM URL:

export YOBOTICS_LCM_URL="udpm://239.255.76.67:7667?ttl=255"
./yobot_sport_client

Common Control Fields¶

Field / API Purpose
Move(vx, vy, vyaw) Sets forward/backward, lateral, and yaw velocity
BodyHeight(h) Sets body-height command
Euler(roll, pitch) Sets body-attitude command
API 1000 PASSIVE
API 1001 DAMP
API 1002 RL_WALK
API 1003 RL_RUN
API 1005 DEVELOPMENT
API 1006 RECOVERY_STAND
API 1007 STAND_DOWN

Reusable control sequence: PASSIVE -> DAMP -> STAND_DOWN -> RECOVERY_STAND ...

Success Criteria¶

  • Controller receives QUAD_ROBOT_CONTROL.
  • The state-feedback channel shows mode and velocity-command changes.
  • The simulated or physical robot responds to limited velocity commands.

Safety Note¶

For hardware tests, start with small velocities such as low-amplitude vx, vy, and vyaw. Do not send large velocities, rapid mode switches, or large body-attitude commands before verification.
