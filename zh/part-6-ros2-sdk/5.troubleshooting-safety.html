6.5 排错与安全操作¶

操作前置条件¶

执行 /control_command 示例前，当前终端必须先加载 ROS 2 和工作空间环境：

source /opt/ros/jazzy/setup.bash
source ~/yobotics_quad48/yobotics_sdk_ros2/install/setup.bash

先按 6.3 启动节点。发布 /control_command 时，请在另一个已经执行上述 source 命令的终端中操作。每次重新打开终端后，都需要重新执行这两条 source 命令。

常见问题¶

现象 原因与处理
Unknown topic '/control_command' 控制节点尚未运行，或当前终端未加载工作空间环境
Waiting for at least 1 matching subscription(s)... 发布端未发现订阅者，检查节点启动终端的日志
No module named 'em' Conda Python 覆盖系统 Python；构建时指定 /usr/bin/python3
节点启动后立即退出 检查依赖、工作空间构建结果和启动日志
模式已切换但机器人不移动 确认模式为 rl_walk，并持续发布速度
运动约 0.5 秒后停止 速度消息没有持续更新，使用 --rate 10

快速检查¶

source /opt/ros/jazzy/setup.bash
source ~/yobotics_quad48/yobotics_sdk_ros2/install/setup.bash
ros2 node list
ros2 topic info /control_command

如果节点不存在，回到 6.3 重新启动。如果订阅者数量为 0，检查两个终端是否使用 相同 ROS 2 环境。

安全操作顺序¶

  1. 新命令先在仿真或安全支架上验证。
  2. 确认急停可用，机器人周围无人员和障碍物。
  3. 使用 recovery_stand 站起并等待姿态稳定。
  4. 切换 rl_walk 后先发送零速度。
  5. 从 0.1 量级的小速度开始测试。
  6. 出现异常时立即按 Ctrl+C 停止速度发布，并发送：
ros2 topic pub --once /control_command sdk_ros2/msg/ControlCommand \
  "{mode: damp, cmd_vel: {}}"

停止后的确认¶

  • 确认机器人不再移动。
  • 确认节点终端没有持续报错。
  • 未查明异常原因前，不重复发送站立或运动命令。

需要了解底层通信和自研算法接入时，阅读第五部分；本部分只覆盖 ROS 2 /control_command 的使用。
