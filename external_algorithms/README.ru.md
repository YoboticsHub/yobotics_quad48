# Демо разработки внешних алгоритмов

Этот каталог содержит демо внешних алгоритмов, которые подключаются к режиму разработки робота через LCM. Каждое демо находится в отдельном подкаталоге и обычно содержит `config.yaml` и `run_algorithm.py`. Демо используют `AlgorithmBase` и `LCMInterface` для приема состояния, выполнения инференса политики или вычислений на основе правил, а также для публикации команд суставов.

Английская версия: [README.md](./README.md). Китайская версия: [README.zh.md](./README.zh.md).

Текущие демо делятся на два типа:

- **Демо на основе DRL**: загружают ONNX-модель политики и генерируют 12-мерные действия суставов из состояния робота и истории действий.
- **Демо на основе модели**: не зависят от файлов DRL-политики; используют явные модели управления, правила движения или аналитические функции для генерации целевых положений суставов.

## Архитектура

- `algorithm_base.py`: базовый класс для загрузки конфигурации, загрузки политики, жизненного цикла режима разработки, цикла инференса и высокочастотной отправки LCM-команд.
- `lcm_interface.py`: обертка LCM, которая подписывается на `development_state_t` и публикует `development_command_t`.
- `walk_algorithm/`: DRL-демо локомоции на основе ONNX-модели политики.
- `wave_algorithm/`: демо явного синусоидального модельного/правилового управления.

## `walk_algorithm/`

`walk_algorithm` — демо с одной ONNX-политикой. Оно использует `policy.type: "onnx"`, а файл политики называется `quadTSnet.onnx`.

Основной процесс:

1. Подписаться на состояние робота в режиме разработки через LCM.
2. Сформировать наблюдения из угловой скорости корпуса, проекции гравитации, желаемой скорости, положения суставов, скорости суставов и предыдущего действия.
3. Запустить ONNX-модель политики и получить 12-мерное действие.
4. Преобразовать действие в 12-мерные целевые положения суставов с помощью `action_scale` и `default_joint_pos`.
5. Сгенерировать PD-команды из `joint_stiffness` / `joint_damping` и опубликовать их через LCM.

## `wave_algorithm/`

`wave_algorithm` — демо явного правилового управления. Оно использует `policy.type: "none"` и не загружает модели политик ONNX или PyTorch.

Основной процесс:

1. Переопределить `_load_policy()` и пропустить загрузку политики.
2. Генерировать синусоидальные действия по времени выполнения в `_run_inference()`.
3. Оставлять hip-суставы в положениях по умолчанию и смещать thigh/calf-суставы синусоидой.
4. Генерировать целевые положения суставов, скорости, моменты, Kp и Kd в `process_action()`.
5. Публиковать команды режима разработки через LCM, чтобы корпус робота двигался вверх и вниз.

## Запуск

Из корня проекта:

```bash
python3 external_algorithms/walk_algorithm/run_algorithm.py --config external_algorithms/walk_algorithm/config.yaml
python3 external_algorithms/wave_algorithm/run_algorithm.py --config external_algorithms/wave_algorithm/config.yaml
```

Или сначала перейдите в каталог демо:

```bash
cd external_algorithms/walk_algorithm
python3 run_algorithm.py --config config.yaml

cd external_algorithms/wave_algorithm
python3 run_algorithm.py --config config.yaml
```

## Конфигурация

### `policy`

- `type`: тип политики. DRL-демо используют `"onnx"`; демо правилового управления могут использовать `"none"`.
- `path`: путь к ONNX-политике. Относительные пути разрешаются от каталога демо.
- `read_metadata`: читать ли параметры модели из метаданных ONNX.
- `warmup_count`: число прогревочных запусков политики.
- `action_threshold`: порог аномального действия.

### `model_params`

- `num_actions`: размерность действия; текущие демо четвероногого робота используют 12.
- `num_obs`: размерность наблюдения.
- `default_joint_pos`: положения суставов по умолчанию.
- `joint_stiffness`: Kp суставов.
- `joint_damping`: Kd суставов.
- `action_scale`: масштабирование действия политики.

### `lcm`

- `url`: URL LCM; пустая строка использует конфигурацию по умолчанию.
- `state_channel`: канал состояния режима разработки, на который выполняется подписка.
- `command_channel`: канал команд режима разработки, в который выполняется публикация.
- `robot_id`: ID робота; должен совпадать с конфигурацией FSM.

### `execution`

- `frequency`: частота инференса политики или вычисления правил.
- `lcm_send_frequency`: частота отправки кэшированной команды LCM, ограничена 200 Hz.
- `auto_start`: автоматически ли входить в режим разработки после получения состояния.
- `auto_end`: автоматически ли выходить из режима разработки при остановке алгоритма.
- `max_execution_time`: максимальное время выполнения; `0` означает без ограничения.

### `rl_mode`

- `true`: демо DRL-политики.
- `false`: демо явного модельного/правилового управления.

### `debug`

- `print_config`: печатать конфигурацию при запуске.
- `print_metadata`: печатать метаданные ONNX во время загрузки.

## Расширение пакета

### Добавление демо на основе DRL

1. Создайте каталог, например `your_drl_algorithm/`.
2. Подготовьте `config.yaml` с путем к ONNX-политике, каналами LCM, частотой выполнения и параметрами модели.
3. В `run_algorithm.py` унаследуйтесь от `AlgorithmBase`.
4. Реализуйте `compute_observation(state)`.
5. Реализуйте `process_action(state, action)`.
6. Переопределите `_run_inference()` или `_load_policy()`, если модель имеет особую структуру входов/выходов.

### Добавление демо на основе модели

1. Задайте `policy.type: "none"`.
2. Переопределите `_load_policy()` и установите `self.policy` в `None`.
3. Генерируйте действия в `_run_inference()` по времени, состоянию, планированию траектории или модели управления.
4. Преобразуйте действия в команды режима разработки в `process_action()`.
5. Задайте `rl_mode.is_rl_mode` согласно ожиданиям FSM, обычно `false`.

## Зависимости

- Python 3.6+
- `numpy`
- `pyyaml`
- Python-привязки `lcm`
- `onnxruntime` для DRL ONNX-политик
- `onnx` при чтении параметров из метаданных ONNX

## Примечания по безопасности

- Убедитесь, что `robot_id`, `state_channel` и `command_channel` точно совпадают с конфигурацией FSM.
- Перед физическим роботом проверьте амплитуду действий, порядок суставов и PD-параметры в симуляции или на безопасной стойке.
- Перед публикацией команд проверяйте выход DRL на NaN, Inf и аномально большие действия.
- После замены модели политики сверяйте `num_actions`, `num_obs`, `default_joint_pos` и `action_scale` с конфигурацией обучения.
- При завершении режима разработки публикуйте команду отключения, чтобы избежать устаревших команд.
