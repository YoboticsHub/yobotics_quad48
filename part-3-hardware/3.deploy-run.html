3.3 实物机器人部署运行¶

用途¶

本节说明如何把部署包发送到机器人端，并启动实物控制器。

前提¶

  • 已完成仿真验证。
  • config.yaml 已按实物机器人核对。
  • 机器人电池、急停、线缆、地面环境和安全区域已确认。
  • 机器人端网络可达。

部署程序¶

把程序发送到机器人内部，脚本参数和目标地址以现场脚本配置为准。发送后应确认机器人端文件完整，尤其是控制器、动态库、配置、模型和资源目录。

启动实物控制器¶

在机器人端项目根目录运行：

bash scripts/run_robot_controller.sh --config config.yaml

脚本会根据 uname -m 自动选择：

架构 控制器目录 动态库目录
x86_64 bin/ybt_ctrl lib/
aarch64 / arm64 bin_rk3588/ybt_ctrl lib_rk3588/

运行顺序¶

  1. 启动控制器后先保持安全模式。
  2. 确认日志没有 SPI、IMU、动态库或配置错误。
  3. 通过遥控器、SDK 或上位机进入 RECOVERY_STAND。
  4. 确认姿态稳定后，再进入 RL_WALK 等运动模式。
  5. 如需测试外部算法，先进入 DEVELOPMENT 模式。

成功标志¶

  • 控制器启动并持续运行。
  • 终端显示的配置文件、可执行文件和库路径正确。
  • 没有 SPI、IMU、LCM 初始化失败。
  • 机器人能进入安全姿态，且 LCM 状态可被监控。

安全提示¶

run_robot_controller.sh 当前会配置 eth1 的 LCM 多播路由。如果现场网卡名不同，需要先按现场网络调整多播配置。启动后若出现异常姿态、异响、失控、抽动或日志持续报错，应立即停止。
