3.5 Logging and Plotting¶

Purpose¶

This section explains how to enable logs during hardware operation, locate log files, and analyze data with CSV plotting tools.

Controller Logs¶

Controller logging switch in config.yaml:

logging:
  enable_logging: true
  log_file_path: "log/robot_log.txt"

View logs:

tail -n 80 log/robot_log.txt
tail -f log/robot_log.txt

RL Data Logs¶

RL_WALK log:

rl_walk:
  enable_logging: false
  log_file_path: "log/log_RL_data.csv"

RL_RUN log:

rl_run:
  enable_logging: false
  log_file_path: "log/log_RL_run_data.csv"

When policy input, output, or action trends need analysis, temporarily enable the corresponding switch and restart the controller.

Motor Trace Log¶

Motor trace logging in config.yaml:

robot_runner:
  enable_motor_trace_logging: false
  motor_trace_log_path: "log/motor_trace.csv"

Without parameters, plotting scripts read built-in paths, usually log/log_RL_data.csv or log/motor_trace.csv. Motor trace logs are used to analyze desired joint position, actual position, velocity, torque, and related data.

Plotting¶

Normal CSV / RL data:

python3 scripts/data_viewer.py
python3 scripts/data_viewer.py log/log_RL_data.csv

Motor trace data:

python3 scripts/motor_trace_viewer.py
python3 scripts/motor_trace_viewer.py log/motor_trace.csv

Success Criteria¶

  • Corresponding log files are generated under log/.
  • CSV files contain headers and continuously updated data rows.
  • Plotting tools can open the files.
  • Curves contain no obvious NaN, Inf, abnormal spikes, or long gaps.

Safety Note¶

Do not keep too many high-frequency logs enabled for long hardware runs; they may affect disk space and real-time performance. Disable temporary CSV logging after debugging.
