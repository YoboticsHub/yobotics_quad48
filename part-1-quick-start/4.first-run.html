1.4 First Run Workflow¶

Purpose¶

This section gives the recommended first-use sequence for the package and helps avoid jumping directly to hardware operation, which makes troubleshooting difficult and increases safety risk.

Prerequisites¶

  • You are in the project root directory.
  • Conda is installed or another Python runtime is available.
  • The current machine can access scripts/, config_sim.yaml, and resources/ in the package.

Steps¶

1. Prepare the Environment¶

bash scripts/setup_conda_env.sh
conda activate robot_controller

2. Start MuJoCo Simulation¶

bash scripts/start_mujoco.sh --config config_sim.yaml

3. Check LCM Communication in Another Terminal¶

conda activate robot_controller
bash scripts/monitor_lcm.sh --no-gui

4. Build and Run SDK Examples¶

cd yobotics_sdk
mkdir -p build
cd build
cmake ..
make -j4
./yobot_sport_client

After ./yobot_sport_client starts, see section 4.3 for behavior.

5. Check Before Hardware Operation¶

Before switching to the real robot, confirm:

  • simulation.enable_mujoco: false in config.yaml.
  • motor_communication.type, spi_type, SPI devices, and IMU port are correct.
  • Emergency stop, power supply, battery, ground environment, and safety area are confirmed.
  • Any new model or algorithm has completed simulation verification.

Success Criteria¶

  • MuJoCo simulator and controller keep running.
  • LCM monitoring shows channels and message frequency.
  • SDK examples can send control commands or read state, and the simulated robot responds accordingly.
  • Controller logs show no missing assets, missing libraries, Python import failures, or communication initialization failures.

Safety Note¶

Do not change speed limits, torque limits, PD parameters, or safety-check switches during the first run. After the default path is stable, adjust items one at a time.
