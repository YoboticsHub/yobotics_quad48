1.1 软件框架介绍¶

用途¶

Quad48 控制框架用于连接 MuJoCo 仿真、实物控制器、SDK 高层接口、LCM 通信和外部算法开发包。用户可以先在仿真中验证模型和算法，再把相同控制逻辑切换到真实机器人。

框架组成¶

模块 目录 作用
主控制器 user/YBT_Controller/ 管理 FSM 控制模式、RL 策略、开发模式和安全检查
桥接层 robot/ 区分 MuJoCo 仿真桥接和实物硬件桥接
公共控制模块 common/ 腿部控制、状态估计、通信接口、日志工具
MuJoCo 仿真 mujoco_sim/ 通过 LCM 与控制器交换关节状态、关节命令和 IMU 数据
SDK yobotics_sdk/ 封装底层 LCM 通信，提供运动控制、状态读取和 HTTP 示例
外部算法 external_algorithms/ 通过开发者模式接入 Python 自研算法或 ONNX 模型
LCM 类型 lcm-types/ 定义控制、状态、开发模式和关节消息结构

工作关系¶

仿真和实物共用控制器、FSM、RL 策略和安全检查逻辑。两者主要区别在桥接层和配置文件：仿真读取 config_sim.yaml，实物读取 config.yaml。

SDK / WebRTC / 外部算法
        |
        v
      LCM
        |
        v
YBT_Controller + FSM + SafetyChecker
        |
        +-- SimulationBridge -> MuJoCo
        |
        +-- HardwareBridge   -> SPI / IMU / 实物电机

操作建议¶

  1. 初次使用先阅读第一部分，完成环境配置。
  2. 新策略或新算法先进入第二部分，在 MuJoCo 中验证。
  3. 实物运行前进入第三部分，核对 config.yaml 和安全检查。
  4. 高层业务控制优先使用第四部分 SDK。
  5. 需要直接控制关节或接入自研算法时阅读第五部分。

安全提示¶

不要绕过仿真验证直接运行实物。实物机器人运行时，错误模型、错误关节顺序、异常 LCM 通道或过大的 PD 参数都可能导致机器人摔倒、撞击或损坏。
