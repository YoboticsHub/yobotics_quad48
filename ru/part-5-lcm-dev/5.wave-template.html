5.5 wave_algorithm как шаблон управления состоянием суставов¶

Назначение¶

wave_algorithm — это правиловый шаблон управления суставами. Он полезен для изучения чтения состояния режима разработки, генерации 12-мерных целевых значений суставов и публикации PD-команд.

Предварительные условия¶

  • Контроллер вошел в режим DEVELOPMENT.
  • Конфигурация каналов LCM согласована.
  • Симуляция MuJoCo запущена.

Проектирование¶

wave_algorithm не загружает ONNX-модель. Он генерирует действия из синусоиды:

  1. Наследоваться от AlgorithmBase.
  2. Переопределить _load_policy() и пропустить загрузку политики.
  3. Генерировать периодический сигнал по времени в _run_inference().
  4. Оставлять hip-суставы в положениях по умолчанию.
  5. Смещать thigh / calf-суставы синусоидой.
  6. Генерировать joint_des_q, joint_des_qd, joint_des_tau, joint_des_kp и joint_des_kd в process_action().

Запуск¶

python3 external_algorithms/wave_algorithm/run_algorithm.py --config external_algorithms/wave_algorithm/config.yaml

Или сначала перейдите в каталог:

cd external_algorithms/wave_algorithm
python3 run_algorithm.py --config config.yaml

Критерии успешного выполнения¶

  • После запуска программа получает состояние режима разработки.
  • Мониторинг LCM показывает Y15_development_command.
  • Суставы робота в симуляции периодически движутся ожидаемым образом.
  • После выхода алгоритма не остается активной команды.

Значение конфигурации и действий¶

wave_algorithm использует policy.type: none, то есть ONNX-модель не загружается. Базовый класс все равно запускает прием состояния, цикл инференса и отправку LCM в едином жизненном цикле, а _load_policy() напрямую задает policy=None.

Текущая конфигурация использует motion.frequency = 0.1 Hz и motion.amplitude = 0.5. В каждой ноге порядок суставов: hip, thigh, calf. Hip сохраняет угол по умолчанию; thigh использует amplitude * sin(phase); calf использует -2 * amplitude * sin(phase).

process_action() в итоге генерирует пять 12-мерных массивов:

Поле Текущее поведение
joint_des_q default_joint_pos + action
joint_des_qd все 0
joint_des_tau все 0
joint_des_kp использует joint_stiffness, сейчас 60
joint_des_kd использует joint_damping, сейчас 2.0

Поэтому action — это смещение положения суставов, а не момент. Углы по умолчанию [0.0, -0.8, 1.6] повторяются для четырех ног. При изменениях сохраняйте 12 размерностей и правильный порядок суставов.

Процесс настройки параметров для начинающих¶

  1. Оставьте policy.type равным none.
  2. Перед первым запуском уменьшите motion.amplitude до 0.05-0.10; не используйте сразу 0.5.
  3. Оставьте motion.frequency равным 0.1 и подтвердите направление движения в MuJoCo.
  4. Перед повторным запуском меняйте только один параметр; не меняйте амплитуду, частоту и PD одновременно.
  5. Используйте monitor_lcm.sh --no-gui, чтобы проверить непрерывность 12-мерных целей в Y15_development_command.
  6. Увеличивайте амплитуду постепенно только после стабильной симуляции.

Устранение неполадок¶

Симптом Возможная причина Проверка
Направление сустава обратное Неверно понят угол по умолчанию или направление сустава Дайте одному суставу очень малое смещение и наблюдайте сустав за суставом
Робот трясется Амплитуда, частота, Kp или Kd слишком велики Сначала уменьшите амплитуду и Kp
Hip тоже движется Неверный индекс действия Проверьте индекс leg_id * 3 + joint
Нет команды Не включен DEVELOPMENT или нет состояния Мониторьте каналы состояния и команд вместе

Примечание по безопасности¶

Перед аппаратными тестами уменьшите амплитуду действия и подтвердите направление каждого сустава, угол по умолчанию, Kp, Kd и период движения. Правиловые алгоритмы не имеют защиты на уровне модели; неверные параметры напрямую отражаются в командах суставов.
