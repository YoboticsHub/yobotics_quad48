5.4 Режим разработки¶

Назначение¶

Режим разработки позволяет внешним Python-алгоритмам получать состояние робота через LCM и публиковать 12-мерные команды суставов. Контроллер реагирует на команды режима разработки только после входа в режим DEVELOPMENT.

Предварительные условия¶

  • Контроллер запущен.
  • SDK, пульт или другая точка управления может переключить режим в DEVELOPMENT.
  • robot_id, state_channel и command_channel в конфигурации внешнего алгоритма совпадают с контроллером.
  • Сеть LCM для MuJoCo или физического робота работает нормально.

Рабочий процесс¶

  1. Контроллер работает и рассылает текущее состояние.
  2. SDK или другая точка управления переключает режим управления в DEVELOPMENT.
  3. Внешний алгоритм подписывается на Y15_development_state.
  4. Внешний алгоритм публикует Y15_development_command.
  5. Контроллер проверяет режим и команду, затем выполняет управление суставами.
  6. При выходе внешний алгоритм публикует команду отключения или безопасную команду.

Вход в режим разработки¶

./yobot_sport_client -> нажмите 5 для входа в DEVELOPMENT, согласно раскладке клавиатуры SDK.

SDK mode number:

Номер Режим
1005 DEVELOPMENT

Запустите Python-пакет разработки после входа в режим разработки:

python3 external_algorithms/wave_algorithm/run_algorithm.py --config external_algorithms/wave_algorithm/config.yaml

Критерии успешного выполнения¶

  • Внешний алгоритм непрерывно получает development_state_t.
  • Контроллер находится в режиме DEVELOPMENT.
  • monitor_lcm.sh показывает каналы состояния и команд режима разработки.
  • После выхода алгоритма робот возвращается в безопасное состояние.

Логика на стороне контроллера¶

Точка входа контроллера — FSM_State_Development.cpp. Внешние команды записываются в 12 целевых значений суставов только когда FSM находится в DEVELOPMENT, robot_id команды совпадает с конфигурацией контроллера, а enable_development_mode равен 1.

Логика Описание
Публикация состояния Публикует development_state_t в Y15_development_state
Подписка на команды Подписывается на development_command_t в Y15_development_command
Проверка robot_id Команды с несовпадающим ID игнорируются
enable_development_mode 1 означает внешний захват управления; 0 завершает внешний захват
Timeout 50 ms После активации отсутствие новой команды более 50 ms автоматически завершает внешний захват
Самопроверка После выхода из захвата проверяет roll/pitch; при ошибке очищает управляющие команды

Контроллер записывает joint_des_q, joint_des_qd, joint_des_tau, joint_des_kp и joint_des_kd напрямую в целевые значения суставов. Массивы, публикуемые Python-алгоритмом, уже должны быть финальными исполняемыми командами.

Значение конфигурации¶

Контроллер и внешние алгоритмы должны использовать одинаковые robot_id, Y15_development_state и Y15_development_command. Пустой lcm.url использует URL по умолчанию. При проблемах между машинами или несколькими интерфейсами сначала проверьте сеть LCM и подтвердите через скрипт мониторинга.

Полная последовательность выполнения¶

Этап Операция Ожидаемый результат
1 Запуск контроллера Состояние публикуется
2 Переключение в DEVELOPMENT FSM входит в режим разработки
3 Запуск алгоритма Конфигурация загружается, подписка на состояние начинается
4 Получение первого кадра состояния Автостарт и первичный захват с текущими углами суставов
5 Инференс или вычисление правил Последняя 12-мерная команда обновляется
6 Поток отправки LCM Отправляет с заданной частотой, ограниченной 200 Hz
7 Выход из алгоритма Отправляет команду отключения, контроллер выходит из внешнего захвата

Устранение неполадок¶

Симптом Возможная причина Проверка
В командах есть данные, но робот не движется FSM не в DEVELOPMENT Проверьте номер режима SDK 1005
Контроллер игнорирует команды Не совпадает robot_id Проверьте конфигурацию контроллера и алгоритма
Движется кратко и выходит Интервал команд превышает 50 ms Проверьте сеть LCM и частоту отправки
Команды очищаются после выхода Самопроверка roll/pitch не прошла Проверьте IMU, позу и журналы контроллера

Значение по умолчанию в примерах часто "Y15", но это только строка сопоставления и не означает, что модель робота обязана быть Y15.

Примечание по безопасности¶

Не считайте, что команды внешнего алгоритма действуют вне режима DEVELOPMENT. При работе с физическим роботом перед входом в режим разработки подтвердите устойчивую позу, нулевую команду скорости и безопасное расстояние для персонала.
