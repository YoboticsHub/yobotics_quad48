2.1 Purpose of MuJoCo Simulation¶

Purpose¶

MuJoCo simulation verifies the controller, RL policies, LCM communication, and user-developed algorithms without hardware risk. It is a required step before hardware deployment.

What Can Be Verified¶

Verification target Description
Controller startup Confirm that YBT_Controller, FSM, configuration files, and dependent libraries run correctly
Predeployed models Verify that ONNX models and parameters for RL_WALK and RL_RUN match
LCM communication Verify joint state, joint command, IMU, SDK, and development-mode channels
SDK control Verify high-level velocity commands, mode switching, and state reading
External algorithms Verify wave_algorithm, walk_algorithm, or custom algorithms
CSV logs Verify logging switches, data output, and plotting tools

Relationship Between Simulation and Hardware¶

Simulation and hardware use the same controller core logic, but the low-level data sources are different:

  • Simulation: MuJoCo publishes joint state and IMU data and receives controller joint commands.
  • Hardware: the hardware bridge reads motor, IMU, remote-control, and SPI data and sends real motor commands.

Operating Advice¶

  1. After replacing an ONNX model, verify motion stability in MuJoCo first.
  2. After modifying an external algorithm, confirm joint order, action amplitude, and PD parameters in MuJoCo first.
  3. After changing LCM messages or channels, verify messages with monitor_lcm.sh first.
  4. After simulation passes, continue to the hardware deployment workflow in sections 3.1 to 3.3.
  5. Simulation startup is covered in 2.2, model verification in 2.3, and debugging in 2.4.

Safety Note¶

Passing simulation does not guarantee hardware safety. Hardware still requires checks for motor direction, SPI devices, IMU type, robot model, ground conditions, and emergency-stop capability.
