5.5 以 wave_algorithm 为标准模板讲关节状态控制¶

用途¶

wave_algorithm 是基于规则的关节控制模板，适合学习如何读取开发模式状态、生成 12 维关节目标并发布 PD 命令。

前提¶

  • 控制器已进入 DEVELOPMENT 模式。
  • LCM 通道配置一致。
  • 已完成 MuJoCo 仿真启动。

设计思路¶

wave_algorithm 不加载 ONNX 模型，而是通过正弦波生成动作：

  1. 继承 AlgorithmBase。
  2. 覆盖 _load_policy()，跳过策略加载。
  3. 在 _run_inference() 中根据时间生成周期信号。
  4. hip 关节保持默认位置。
  5. thigh / calf 关节按正弦波偏移。
  6. 在 process_action() 中生成 joint_des_q、joint_des_qd、joint_des_tau、joint_des_kp、joint_des_kd。

运行方式¶

python3 external_algorithms/wave_algorithm/run_algorithm.py --config external_algorithms/wave_algorithm/config.yaml

也可以进入目录后运行：

cd external_algorithms/wave_algorithm
python3 run_algorithm.py --config config.yaml

成功标志¶

  • 程序启动后能收到开发模式状态。
  • LCM 监控中能看到 Y15_development_command。
  • 仿真中机器人关节按预期周期运动。
  • 算法退出时没有命令残留。

配置和动作含义¶

wave_algorithm 的 policy.type 是 none，表示不加载 ONNX 模型。基类仍会按统一生命周期启动状态接收、推理循环和 LCM 发送线程，但 _load_policy() 会直接设置 policy=None。

当前配置中 motion.frequency 为 0.1 Hz，motion.amplitude 为 0.5。每条腿按 hip、thigh、calf 排列，hip 保持默认角，thigh 使用 amplitude * sin(phase)，calf 使用 -2 * amplitude * sin(phase)。

process_action() 最终生成以下五组 12 维数据：

字段 当前行为
joint_des_q default_joint_pos + action
joint_des_qd 全部为 0
joint_des_tau 全部为 0
joint_des_kp 使用 joint_stiffness，当前为 60
joint_des_kd 使用 joint_damping，当前为 2.0

因此 action 是关节位置偏移，不是力矩。默认角为四条腿重复的 [0.0, -0.8, 1.6]，修改时必须保持 12 维和正确关节顺序。

初学者改参流程¶

  1. 保持 policy.type 为 none。
  2. 先把 motion.amplitude 降到 0.05 到 0.10。
  3. 保持 motion.frequency 为 0.1，在 MuJoCo 中确认运动方向。
  4. 只改一个参数再重跑，避免同时修改幅值、频率和 PD。
  5. 用 monitor_lcm.sh --no-gui 检查 Y15_development_command 的 12 维目标是否连续。
  6. 确认仿真稳定后，再逐步增加幅值。

常见问题¶

现象 可能原因 排查方法
关节方向反了 默认角或关节方向理解错误 只给一个关节很小偏移，逐关节观察
机器人抖动 幅值、频率、Kp 或 Kd 过大 先降低 amplitude 和 Kp
hip 也在动 动作索引写错 检查 leg_id * 3 + joint 的索引
没有命令 未进入 DEVELOPMENT 或没有状态 同时监控状态和命令通道

安全提示¶

实物测试前必须降低动作幅值，并确认每个关节方向、默认角、Kp、Kd 和动作周期。规则算法没有模型保护，参数错误会直接反映到关节命令。
