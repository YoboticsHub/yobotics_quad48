5.6 walk_algorithm ONNX Simulation Deployment¶

Purpose¶

walk_algorithm is a development-package example based on an ONNX policy model. It is used to verify user-developed or pretrained walking policies in development mode.

Prerequisites¶

  • MuJoCo simulation has started.
  • The controller can enter DEVELOPMENT mode.
  • external_algorithms/walk_algorithm/quadTSnet.onnx exists.
  • Python environment has onnxruntime, numpy, pyyaml, and LCM bindings installed.

Key Configuration¶

Config item Description
policy.type ONNX example uses "onnx"
policy.path ONNX model path
model_params.num_obs Model observation dimension
model_params.num_actions Current quadruped action dimension is 12
model_params.default_joint_pos Default joint angles
model_params.action_scale Action scaling
execution.frequency Policy inference frequency
execution.lcm_send_frequency LCM command sending frequency, capped at 200 Hz

Run¶

python3 external_algorithms/walk_algorithm/run_algorithm.py --config external_algorithms/walk_algorithm/config.yaml

Verification Flow¶

  1. Start MuJoCo simulation.
  2. Switch the controller to DEVELOPMENT.
  3. Run walk_algorithm.
  4. Use monitor_lcm.sh --no-gui to check development-mode state and commands.
  5. Observe gait stability in MuJoCo Viewer.
  6. Check logs for NaN, Inf, dimension mismatch, or action-threshold errors.

Success Criteria¶

  • ONNX model loads successfully.
  • Policy warmup has no errors.
  • Observation and action dimensions match.
  • The robot responds stably to policy output in simulation.

ONNX Loading and Real-State Warmup¶

AlgorithmBase creates an onnxruntime.InferenceSession when policy.type is onnx. Currently read_metadata is false, so model_params come from config.yaml. If metadata reading is enabled, it also tries to read joint names, default angles, Kp, Kd, action scale, and dimensions.

When warmup_count is 500, the program waits for real development_state_t, builds observations, runs inference 500 times, and checks whether action exceeds action_threshold. If warmup makes no progress, it usually means Y15_development_state is not received, not that the model itself failed to load.

45-Dimensional Observation and History¶

walk_algorithm.compute_observation() currently uses 45 dimensions:

Range Content
0:3 state.omega, body angular velocity
3:6 Gravity projection calculated from state.quat
6:9 [state.v_des[0], state.v_des[1], state.omega_des[2]]
9:21 state.joint_q - default_joint_pos
21:33 state.joint_qd
33:45 Previous action buffer

Observations are clipped to a reasonable range. The base class also maintains a history-observation queue. The first observation fills the history, and later observations are appended from old to new. Current ONNX inference assumes the model has exactly two inputs: current observation and flattened history observation.

Action Processing and Error Checks¶

Action processing formula:

joint_positions = action * action_scale + default_joint_pos
joint_velocities = 0
joint_torques = 0
joint_kp = model_params.joint_stiffness
joint_kd = model_params.joint_damping

The code checks NaN/Inf in actions or targets, action length, scale-array length, default-angle length, and final 12-dimensional length. If an action is abnormal, it tries to use the previous action buffer; if that is still abnormal, it skips the command. These checks do not replace verification of observation order and training configuration.

Replace With Your Own Model¶

When replacing the ONNX model, check all of these together:

Item Requirement
num_obs Matches training observation dimension
History input Input count, history length, and flatten order match
num_actions Output dimension is 12
default_joint_pos Matches the training environment default angles
action_scale Matches training and simulation deployment
Kp/Kd Does not exceed the simulation-verified range
Joint order Model output matches development_command_t order
Input names Current code assumes exactly two ONNX inputs

If the model needs only one input or a different history structure, modify _run_inference() first and verify in simulation.

Troubleshooting¶

Symptom Possible cause Check
Policy file not found Wrong policy.path Confirm model path relative to the config file directory
Warmup stuck No real state Monitor Y15_development_state
Model input error Input count or dimension mismatch Check ONNX input information and history length
Action exceeds threshold Model output or observation construction abnormal Check observation order, default angles, and command scale
Simulation diverges Scale, joint order, or PD mismatch Reduce action_scale and PD, return to small-amplitude verification

Safety Note¶

After replacing an ONNX model, check observation construction, action scale, default joint angles, joint order, Kp, Kd, and output clipping together. Do not deploy a model to hardware merely because it runs at the script level.
