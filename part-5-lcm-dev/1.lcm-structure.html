5.1 LCM 结构¶

用途¶

本节说明控制框架中的 LCM 通信结构，帮助用户理解 SDK、MuJoCo、控制器和外部算法之间的数据流。

LCM 是什么¶

LCM 是控制框架中用于进程间、机器间传递消息的通信机制。控制器、MuJoCo、SDK、WebRTC 和外部算法通过 LCM 发布和订阅消息，实现控制命令下发、状态回读、仿真关节数据交换和开发模式算法接入。

LCM 通道名可以理解为消息频道，例如 QUAD_ROBOT_CONTROL、leg_control_data。消息内容的字段和类型由 lcm-types/ 下的 .lcm 文件定义，通信双方必须使用一致的通道名和消息类型。

通信关系¶

SDK / HTTP / WebRTC
        |
        | QUAD_ROBOT_CONTROL / QUAD_ROBOT_STATE
        v
YBT_Controller
        |
        +-- leg_control_command / leg_control_data
        |       |
        |       +-- MuJoCo 仿真或硬件通信
        |
        +-- Y15_development_command / Y15_development_state
                |
                +-- external_algorithms Python 开发包

主要通道¶

通道 方向 用途
QUAD_ROBOT_CONTROL SDK / WebRTC -> 控制器 高层运动控制
QUAD_ROBOT_STATE 控制器 -> SDK / WebRTC 高层状态回读
leg_control_data 仿真 / 硬件 -> 控制器 关节状态
leg_control_command 控制器 -> 仿真 / 硬件 关节命令
Y15_development_state 控制器 -> 外部算法 开发模式状态
Y15_development_command 外部算法 -> 控制器 开发模式关节命令

操作建议¶

  1. 修改通道名前，先确认所有通信端都同步修改。
  2. 收不到数据时，先用 bash scripts/monitor_lcm.sh --no-gui 查看通道是否存在。
  3. 修改 .lcm 文件后运行 bash scripts/generate_lcm_types.sh。
  4. 异机部署时确保 LCM URL、网卡和多播路由一致。

安全提示¶

LCM 是无连接消息通信。发布端和订阅端通道名或消息类型不一致时，系统不会自动修复，可能表现为无响应、状态缺失或控制命令残留。
