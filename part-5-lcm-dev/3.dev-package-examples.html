5.3 开发包示例¶

用途¶

本节介绍 external_algorithms/ 开发包结构和两个内置示例。读完后，应能看懂外部算法如何读取状态、生成 12 维关节命令、通过 LCM 发给控制器，并知道新建自研算法目录时应从哪些文件开始改。

目录结构¶

external_algorithms/
├── README.md
├── algorithm_base.py
├── lcm_interface.py
├── walk_algorithm/
│   ├── config.yaml
│   ├── run_algorithm.py
│   └── quadTSnet.onnx
└── wave_algorithm/
    ├── README.md
    ├── config.yaml
    └── run_algorithm.py

核心文件¶

文件 作用
algorithm_base.py 配置加载、策略加载、开发模式生命周期、推理循环、LCM 发送
lcm_interface.py 订阅开发模式状态，发布开发模式命令
walk_algorithm/ 基于 ONNX 的强化学习行走示例
wave_algorithm/ 基于规则的关节正弦波控制示例

整体架构¶

外部算法开发包可以理解为三层：

层级 主要文件 作用
通信层 lcm_interface.py 订阅控制器状态通道，发布开发模式命令通道
生命周期层 algorithm_base.py 加载配置、策略预热、推理线程、LCM 发送线程、退出命令
算法层 两个示例的 run_algorithm.py 根据状态生成 action，并转换成 12 维 PD 命令

控制器侧在 FSM_State_Development.cpp 中广播 development_state_t，并在收到合法的 development_command_t 后写入关节目标。外部算法侧不直接操作电机，只负责发布开发模式命令。

AlgorithmBase 负责什么¶

AlgorithmBase 是所有外部算法的公共底座。自研算法通常只需要继承它，并实现观测和动作处理。

功能 说明
配置加载 读取算法目录下的 config.yaml
策略加载 policy.type: "onnx" 时加载 ONNX；规则算法可重写 _load_policy()
策略预热 warmup_count > 0 时用真实状态推理并检查 action 阈值
推理线程 按 execution.frequency 调用观测、推理和动作处理
发送线程 按 execution.lcm_send_frequency 发送最近命令，最高 200 Hz
自动开始/结束 自动发送启用命令，退出时发送 enable_development_mode: 0

算法子类最重要的两个入口是：

方法 作用
compute_observation(state) 把 development_state_t 转成观测向量
process_action(state, action) 转成位置、速度、力矩、Kp、Kd 五组 12 维数组

LCMInterface 负责什么¶

LCMInterface 只做通信封装，不做控制逻辑。它订阅 Y15_development_state，解码后按 robot_id 过滤；发送时构造 development_command_t 并发布到 Y15_development_command。

配置项 说明
lcm.url 空字符串表示使用默认 URL
lcm.state_channel 当前示例为 Y15_development_state
lcm.command_channel 当前示例为 Y15_development_command
lcm.robot_id 状态和命令匹配的机器人 ID

运行示例¶

行走策略：

python3 external_algorithms/walk_algorithm/run_algorithm.py --config external_algorithms/walk_algorithm/config.yaml

波形控制：

python3 external_algorithms/wave_algorithm/run_algorithm.py --config external_algorithms/wave_algorithm/config.yaml

运行前应先启动 MuJoCo 或实物控制器，并让控制器进入 DEVELOPMENT。如果只启动 Python 脚本但没有控制器状态，脚本会收不到 development_state_t。

新建自研算法目录¶

建议从 wave_algorithm/ 复制目录开始，因为它没有模型依赖。

  1. 复制目录并改名，例如 my_algorithm/。
  2. 修改 config.yaml 中的 algorithm_name 和 LCM 配置。
  3. 规则算法保留 policy.type: "none"；ONNX 算法设置模型路径。
  4. 在 run_algorithm.py 中实现 compute_observation() 和 process_action()。
  5. 确认观测顺序、动作维度、默认角、动作缩放、关节顺序和 PD 参数。
  6. 先用小幅值在仿真中运行，再用 bash scripts/monitor_lcm.sh --no-gui 观察通道。

配置块¶

配置块 作用
policy 策略类型、模型路径、预热和异常动作阈值
model_params 观测维度、动作维度、默认关节角、Kp、Kd、动作缩放
lcm LCM URL、状态通道、命令通道、机器人 ID
execution 推理频率、LCM 发送频率、自动开始和结束
rl_mode 是否按强化学习模式处理
debug 是否打印配置和模型 metadata

常见问题¶

现象 可能原因 排查方法
一直等不到状态 控制器未启动、LCM 网络不通、通道名不一致 先运行 bash scripts/monitor_lcm.sh --no-gui
状态存在但算法不动作 未进入 DEVELOPMENT 或 robot_id 不匹配 核对模式编号 1005 和 robot_id: "Y15"
ONNX 加载失败 路径或依赖错误 确认模型存在并安装 onnxruntime

安全提示¶

外部算法应先在 MuJoCo 中运行。确认状态接收、命令发布、关节顺序、动作幅值和退出逻辑正常后，再考虑实物部署。
