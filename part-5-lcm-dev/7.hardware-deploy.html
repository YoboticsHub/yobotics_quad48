5.7 自研算法实物部署¶

用途¶

本节说明用户自研算法从仿真部署到实物部署的切换流程。实物部署的目标不是让算法马上跑起来，而是用可观察、可停止、可回退的方式确认仿真逻辑在真实机器人上仍然成立。

默认原则：先仿真，再支架或安全区域，先小幅、短时间测试；有异常立即回退到 DAMP 或停止控制器，回到仿真排查，不用增大 PD、扭矩或限制值掩盖问题。

前提¶

  • 算法已在 MuJoCo 中完成验证。
  • monitor_lcm.sh 能看到开发模式状态和命令。
  • 算法退出时能发布禁用命令或安全命令。
  • 实物 config.yaml 已核对机器人型号、SPI、IMU、LCM 和安全检查。
  • 急停、支架或安全区域已准备。
  • 现场人员知道如何切回 DAMP 或停止控制器。

仿真到实物检查清单¶

项目 要求
配置一致性 核对 robot_id、通道名、模型参数
LCM 通道 能看到 Y15_development_state 和 Y15_development_command
SPI / IMU 控制器无通信错误，姿态数据无明显跳变
机器人姿态 roll/pitch 稳定，未超过开发者模式自检阈值
关节顺序 与 development_command_t 的 12 维顺序一致
默认关节角 与实物初始姿态一致
PD 参数 不超过仿真验证范围
动作幅值 首次使用小幅值和短时间
退出路径 Ctrl+C、切 DAMP、急停均已确认可用

实物部署步骤¶

  1. 将算法目录、配置文件和模型文件放入机器人端软件包。
  2. 确认算法配置中的 LCM URL、robot_id、状态通道和命令通道与 config.yaml 一致。
  3. 启动实物控制器：
bash scripts/run_robot_controller.sh --config config.yaml
  1. 读取状态并确认机器人姿态稳定。
  2. 启动 LCM 监控：
bash scripts/monitor_lcm.sh --no-gui
  1. 通过 SDK 或控制入口进入 DEVELOPMENT。
  2. 先运行降低幅值后的 wave_algorithm，确认方向和退出逻辑。
  3. 再运行自研算法，例如：
python3 external_algorithms/walk_algorithm/run_algorithm.py --config external_algorithms/walk_algorithm/config.yaml
  1. 使用日志和 LCM 监控观察状态：
bash scripts/monitor_lcm.sh --no-gui
tail -f log/robot_log.txt
  1. 首次运行只保持短时间，确认状态、命令和姿态稳定后主动退出。

成功标志¶

  • 实物控制器无 SPI、IMU、LCM 和安全检查错误。
  • 外部算法能收到真实机器人状态。
  • 机器人只执行小幅、稳定、可停止的动作。
  • 算法退出后机器人进入安全状态。

上实物前复核¶

项目 要求
动作幅值 先使用小幅值和短时间测试
关节顺序 与 development_command_t 完全一致
PD 参数 不超过仿真验证范围
频率 不超过控制器和 LCM 能稳定处理的范围
安全检查 保持开启
急停 现场可立即触发

监控重点¶

监控项 正常现象
Y15_development_state 持续更新，robot_id 为 Y15
Y15_development_command 运行时持续更新，退出时 enable_development_mode 为 0
控制器日志 无 SPI、IMU、LCM 和安全检查错误
roll/pitch 姿态稳定，退出外部接管后自检通过
关节目标 连续，无 NaN/Inf 和明显突变
实际关节 跟随目标，无异常抖动、异响或饱和

异常处理¶

异常 处理
姿态快速变化 立即停止算法，切回 DAMP 或急停
关节方向不对 停止实物测试，回仿真逐关节核对顺序
命令丢失或超时 检查 LCM 频率、网络和发送线程
自检失败 检查 IMU、支架姿态和控制器日志
NaN/Inf 或维度错误 停止部署，回到模型输入排查
抖动或异响 降低幅值和 PD，回仿真，不继续实物调参

安全提示¶

如果实物动作与仿真不一致，立即停止并回到仿真排查。不要通过增大 PD、扭矩或速度上限来掩盖模型、状态估计或关节顺序问题。
