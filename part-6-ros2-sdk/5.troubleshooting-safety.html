6.5 Troubleshooting and Safety¶

Prerequisites Before Commands¶

Before running any /control_command example, load ROS 2 and the workspace in the current terminal:

source /opt/ros/jazzy/setup.bash
source ~/yobotics_quad48/yobotics_sdk_ros2/install/setup.bash

Start the node as shown in Section 6.3 first. Then publish /control_command from another terminal that has also run the two source commands above. Run these two source commands again every time you open a new terminal.

Common Issues¶

Symptom Cause and action
Unknown topic '/control_command' The node is not running, or the workspace environment is not loaded
Waiting for at least 1 matching subscription(s)... The publisher cannot find the subscriber; inspect the node terminal
No module named 'em' Conda overrides the system Python; build with /usr/bin/python3
The node exits immediately Check dependencies, build output, and startup logs
The mode changes but the robot does not move Confirm rl_walk and continuously publish velocity
Motion stops after about 0.5 seconds Velocity is not being refreshed; use --rate 10

Quick Check¶

source /opt/ros/jazzy/setup.bash
source ~/yobotics_quad48/yobotics_sdk_ros2/install/setup.bash
ros2 node list
ros2 topic info /control_command

If the node is missing, restart it using Section 6.3. If the subscription count is zero, verify that both terminals use the same ROS 2 environment.

Safe Operating Sequence¶

  1. Test new commands in simulation or on a safety stand.
  2. Confirm that the emergency stop works and clear people and obstacles.
  3. Use recovery_stand and wait for a stable posture.
  4. After switching to rl_walk, send zero velocity first.
  5. Start testing with low values around 0.1.
  6. If anything is abnormal, press Ctrl+C and immediately send:
ros2 topic pub --once /control_command sdk_ros2/msg/ControlCommand \
  "{mode: damp, cmd_vel: {}}"

After Stopping¶

  • Confirm that the robot is no longer moving.
  • Confirm that the node terminal is not repeatedly reporting errors.
  • Do not repeat standing or motion commands until the cause is understood.

For low-level communication and custom algorithm integration, read Part 5. This part covers only ROS 2 /control_command usage.
