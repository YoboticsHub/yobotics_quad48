# 4.8 SDK Demo 使用

## 用途

本节汇总 SDK Demo 的使用顺序、环境变量和常见问题。

## Demo 列表

| 程序 | 源码 | 作用 |
| --- | --- | --- |
| `yobot_sport_client` | `example/sport_client.cpp` | 发送运动控制命令 |
| `yobot_robot_state_client` | `example/robot_state_client.cpp` | 读取机器人状态 |
| `yobot_http_server` | `example/http_server.cpp` | 启动 HTTP 控制服务 |

## 推荐使用顺序

1. 先启动仿真或实物控制器（仿真详见2.2/4.5章节，实物见3.3/4.6章节）。
2. 运行 `yobot_robot_state_client`，确认状态可读。
3. 运行 `yobot_sport_client`，发送小幅控制命令。
4. 需要集成 HTTP 时，再启动 `yobot_http_server`。

## LCM URL

同机运行通常可以使用默认 LCM 地址。异机部署时建议显式设置：

```bash
export YOBOTICS_LCM_URL="udpm://239.255.76.67:7667?ttl=255"
```

控制器、SDK、WebRTC 和外部算法必须保持一致。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| Demo 启动后无状态 | 检查控制器、LCM URL、防火墙和组播路由 |
| 控制命令无响应 | 确认机器人模式可接收 SDK 控制 |
| HTTP token 错误 | 检查请求头 `Authorization` |
| 异机控制不稳定 | 先用 `monitor_lcm.sh --no-gui` 检查通道频率 |

## 安全提示

SDK Demo 适合验证链路，不建议直接作为无人值守业务程序使用。正式集成时应加入状态确认、超时保护、限幅和异常停止逻辑（详见3.4章节）。
