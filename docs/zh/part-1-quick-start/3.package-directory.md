# 1.3 软件包目录

## 用途

本节说明软件包中各目录的职责，方便用户定位配置、脚本、模型、SDK 和开发者示例。


## 关键目录

| 路径 | 作用 |
| --- | --- |
| `config.yaml` | 实物机器人默认配置 |
| `config_sim.yaml` | MuJoCo 仿真默认配置 |
| `actor_model/` | `RL_WALK`、`RL_RUN` 使用的 ONNX 策略模型 |
| `resources/` | 机器人 URDF、MuJoCo XML、mesh 等资源 |
| `scripts/` | 环境配置、仿真启动、实物启动、LCM 监控、数据绘图脚本 |
| `mujoco_sim/` | MuJoCo 仿真程序 |
| `external_algorithms/` | Python 自研算法接入框架和示例 |
| `yobotics_sdk/` | C++ SDK、示例程序和 HTTP 控制服务 |
| `lcm-types/` | LCM 消息定义及生成代码 |

## 配置文件定位

| 文件 | 场景 | 关键项 |
| --- | --- | --- |
| `config_sim.yaml` | 仿真 | `simulation.enable_mujoco: true`、`motor_communication.type: lcm` |
| `config.yaml` | 实物 | `simulation.enable_mujoco: false`、`motor_communication.type: spi_legacy` |

## 操作建议

1. 不确定当前场景时，先确认使用的是 `config_sim.yaml` 还是 `config.yaml`。
2. 不确定脚本参数时，优先运行 `bash scripts/<script>.sh --help`。
3. 修改 LCM 消息后，使用 `bash scripts/generate_lcm_types.sh` 重新生成类型。


## 安全提示

不要混用仿真配置和实物配置。特别是 `simulation.enable_mujoco`、`motor_communication.type`、`spi_type`、IMU 端口和 LCM 通道必须与运行场景一致。
