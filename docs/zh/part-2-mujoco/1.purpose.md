# 2.1 MuJoCo 仿真的作用

## 用途

MuJoCo 仿真用于在没有实物风险的环境中验证控制器、RL 策略、LCM 通信和用户自研算法。它是实物部署前的必经步骤。

## 可验证内容

| 验证对象 | 说明 |
| --- | --- |
| 控制器启动 | 确认 `YBT_Controller`、FSM、配置文件和依赖库可运行 （见2.2～2.4章节）|
| 预部署模型 | 验证 `RL_WALK`、`RL_RUN` 对应 ONNX 模型和参数是否匹配 （见2.2～2.4章节）|
| LCM 通信 | 验证关节状态、关节命令、IMU、SDK 和开发模式通道 （见2.2～2.4章节）|
| SDK 控制 | 验证高层速度命令、模式切换和状态读取 （见4.5章节）|
| 外部算法 | 验证 `wave_algorithm`、`walk_algorithm` 或用户自研算法（见5整节） |
| CSV 日志 | 验证日志开关、数据输出和绘图工具（见3.5章节） |


## 仿真和实物的关系

仿真和实物使用相同的控制器核心逻辑，但底层数据来源不同：

- 仿真：MuJoCo 发布关节状态和 IMU 数据，接收控制器关节命令。
- 实物：硬件桥接层读取电机、IMU、遥控器和 SPI 数据，并下发真实电机命令。

## 操作建议

1. 每次替换 ONNX 模型后，先在 MuJoCo 中验证动作是否稳定。
2. 每次修改外部算法后，先在 MuJoCo 中确认关节顺序、动作幅值和 PD 参数。
3. 每次修改 LCM 消息或通道后，先用 `monitor_lcm.sh` 验证消息是否存在。
4. 仿真通过后，再进入实物部署流程（见3.1～3.3章节）。
5. 仿真启动见2.2章节，模型验证见2.3章节，调试见2.4章节。

## 安全提示

仿真通过不代表实物一定安全。实物还需要核对电机方向、SPI 设备、IMU 类型、机器人型号、地面条件和急停能力。
