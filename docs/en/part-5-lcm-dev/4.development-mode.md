# 5.4 Development Mode

## Purpose

Development mode lets external Python algorithms receive robot state through LCM and publish 12-dimensional joint commands. The controller responds to development-mode commands only after entering `DEVELOPMENT` mode.

## Prerequisites

- The controller has started.
- SDK, remote controller, or another control entry can switch to `DEVELOPMENT`.
- `robot_id`, `state_channel`, and `command_channel` in the external algorithm configuration match the controller.
- LCM networking for MuJoCo or hardware is normal.

## Workflow

1. The controller runs and broadcasts current state.
2. SDK or another control entry switches control mode to `DEVELOPMENT`.
3. The external algorithm subscribes to `Y15_development_state`.
4. The external algorithm publishes `Y15_development_command`.
5. The controller validates mode and command, then performs joint control.
6. The external algorithm publishes a disable command or safe command on exit.

## Enter Development Mode

```bash
./yobot_sport_client -> press 5 to enter DEVELOPMENT, subject to the SDK keyboard mapping.
```

SDK mode number:

| Number | Mode |
| --- | --- |
| `1005` | `DEVELOPMENT` |

Run the Python development package after entering development mode:

```bash
python3 external_algorithms/wave_algorithm/run_algorithm.py --config external_algorithms/wave_algorithm/config.yaml
```

## Success Criteria

- The external algorithm continuously receives `development_state_t`.
- The controller is in `DEVELOPMENT` mode.
- `monitor_lcm.sh` shows development-mode state and command channels.
- The robot returns to a safe state when the algorithm exits.

## Controller-Side Logic

The controller entry is `FSM_State_Development.cpp`. External commands are written into the 12 joint targets only when FSM is in DEVELOPMENT, command `robot_id` matches controller configuration, and `enable_development_mode` is 1.

| Logic | Description |
| --- | --- |
| State publishing | Publishes `development_state_t` to `Y15_development_state` |
| Command subscription | Subscribes to `development_command_t` on `Y15_development_command` |
| `robot_id` check | Commands with mismatched IDs are ignored |
| `enable_development_mode` | 1 means external takeover; 0 ends external takeover |
| 50 ms timeout | After activation, no new command for more than 50 ms ends external takeover automatically |
| Self-check | After exiting takeover, checks roll/pitch; on failure, clears control commands |

The controller writes `joint_des_q`, `joint_des_qd`, `joint_des_tau`, `joint_des_kp`, and `joint_des_kd` directly into joint targets. Arrays published by the Python algorithm must already be final executable commands.

## Configuration Meaning

Controller and external algorithms must use the same `robot_id`, `Y15_development_state`, and `Y15_development_command`. An empty `lcm.url` uses the default URL. For cross-machine or multi-interface issues, check the LCM network first and verify with the monitor script.

## Complete Runtime Sequence

| Stage | Operation | Expected result |
| --- | --- | --- |
| 1 | Start controller | State is published |
| 2 | Switch to DEVELOPMENT | FSM enters development mode |
| 3 | Start algorithm | Configuration loads and state subscription starts |
| 4 | Receive first state frame | Auto start and take over using current joint angles first |
| 5 | Inference or rule computation | Latest 12-dimensional command updates |
| 6 | LCM sending thread | Sends at configured frequency, capped at 200 Hz |
| 7 | Exit algorithm | Sends disable command and controller exits external takeover |

## Troubleshooting

| Symptom | Possible cause | Check |
| --- | --- | --- |
| Commands have data but robot does not move | FSM is not in DEVELOPMENT | Check SDK mode number `1005` |
| Controller ignores commands | `robot_id` mismatch | Check controller and algorithm configuration |
| Moves briefly then exits | Command interval exceeds 50 ms | Check LCM network and sending frequency |
| Commands clear after exit | roll/pitch self-check failed | Check IMU, posture, and controller logs |

The example default is often `"Y15"`, but this is only a matching string and does not mean the robot model must be Y15.

## Safety Note

Do not assume external algorithm commands are effective outside `DEVELOPMENT` mode. For hardware operation, confirm stable posture, zero velocity command, and personnel distance before entering development mode.
