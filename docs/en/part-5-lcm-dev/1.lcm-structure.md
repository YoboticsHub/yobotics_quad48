# 5.1 LCM Structure

## Purpose

This section explains the LCM communication structure in the control framework so users can understand data flow between SDK, MuJoCo, controller, and external algorithms.

## What Is LCM

LCM is the communication mechanism used by the control framework to pass messages between processes and machines. Controller, MuJoCo, SDK, WebRTC, and external algorithms publish and subscribe to LCM messages for control commands, state feedback, simulation joint-data exchange, and development-mode algorithm integration.

An LCM channel name is like a message topic, for example `QUAD_ROBOT_CONTROL` or `leg_control_data`. Message fields and types are defined by `.lcm` files under `lcm-types/`. Communication peers must use matching channel names and message types.

## Communication Relationship

```text
SDK / HTTP / WebRTC
        |
        | QUAD_ROBOT_CONTROL / QUAD_ROBOT_STATE
        v
YBT_Controller
        |
        +-- leg_control_command / leg_control_data
        |       |
        |       +-- MuJoCo simulation or hardware communication
        |
        +-- Y15_development_command / Y15_development_state
                |
                +-- external_algorithms Python development package
```

## Main Channels

| Channel | Direction | Purpose |
| --- | --- | --- |
| `QUAD_ROBOT_CONTROL` | SDK / WebRTC -> controller | High-level motion control |
| `QUAD_ROBOT_STATE` | controller -> SDK / WebRTC | High-level state feedback |
| `leg_control_data` | simulation / hardware -> controller | Joint state |
| `leg_control_command` | controller -> simulation / hardware | Joint command |
| `Y15_development_state` | controller -> external algorithms | Development-mode state |
| `Y15_development_command` | external algorithms -> controller | Development-mode joint command |

Notes:

1. `Y15_development_*` is a historical channel prefix and is not limited to Y15 robots.
2. E15 and Y15 hardware development mode both use these channels unless the configuration is changed.
3. If channel names change, controller, external-algorithm `config.yaml`, and `robot_id` must be changed together.

## Operating Advice

1. Before changing channel names, confirm that all communication endpoints are updated together.
2. If data is missing, first run `bash scripts/monitor_lcm.sh --no-gui` to see whether the channel exists.
3. After modifying `.lcm` files, run `bash scripts/generate_lcm_types.sh`.
4. For multi-machine deployment, keep LCM URL, network interface, and multicast routes consistent.

## Safety Note

LCM is connectionless message communication. If publisher and subscriber channel names or message types differ, the system will not repair the mismatch automatically. Symptoms may include no response, missing state, or stale control commands.
