# 1.1 Software Framework

## Purpose

The Quad48 control framework connects MuJoCo simulation, the hardware controller, SDK high-level interfaces, LCM communication, and external algorithm packages. Users can first verify models and algorithms in simulation, then switch the same control logic to a real robot.

## Runtime Relationship

Simulation and hardware share the controller, FSM, RL policy, and safety-check logic. The main differences are the bridge layer and the configuration file: simulation reads `config_sim.yaml`; hardware reads `config.yaml`.

```text
SDK / WebRTC / External algorithms
        |
        v
      LCM
        |
        v
YBT_Controller + FSM + SafetyChecker
        |
        +-- SimulationBridge -> MuJoCo
        |
        +-- HardwareBridge   -> SPI / IMU / physical motors
```

The diagram shows control-data flow from top to bottom. Upper-layer commands enter the main controller through LCM, pass through FSM mode switching and safety checks, and then go either through the simulation bridge to MuJoCo or through the hardware bridge to SPI / IMU / motors.

## Operating Advice

1. Read Part 1 first and complete environment setup.
2. Verify every new policy or algorithm in MuJoCo through Part 2.
3. Before hardware operation, read Part 3 and check `config.yaml` plus safety checks.
4. Prefer the SDK in Part 4 for high-level business control.
5. Read Part 5 when direct joint control or custom algorithm integration is required.

## Safety Note

Do not bypass simulation verification and run directly on hardware. Wrong models, wrong joint order, incorrect LCM channels, or excessive PD parameters may cause the robot to fall, collide, or be damaged.
