# 1.3 Package Directory

## Purpose

This section explains the responsibilities of key directories in the software package so users can find configuration, scripts, models, SDK files, and developer examples.

## Key Directories

| Path | Purpose |
| --- | --- |
| `config.yaml` | Default physical-robot configuration |
| `config_sim.yaml` | Default MuJoCo simulation configuration |
| `actor_model/` | ONNX policy models used by `RL_WALK` and `RL_RUN` |
| `resources/` | Robot URDF, MuJoCo XML, meshes, and other assets |
| `scripts/` | Environment setup, simulation startup, hardware startup, LCM monitoring, and plotting scripts |
| `mujoco_sim/` | MuJoCo simulation program |
| `external_algorithms/` | Python custom-algorithm integration framework and examples |
| `yobotics_sdk/` | C++ SDK, example programs, and HTTP control service |
| `lcm-types/` | LCM message definitions and generated code |

## Configuration Files

| File | Scenario | Key items |
| --- | --- | --- |
| `config_sim.yaml` | Simulation | `simulation.enable_mujoco: true`, `motor_communication.type: lcm` |
| `config.yaml` | Hardware | `simulation.enable_mujoco: false`, `motor_communication.type: spi_legacy` |

## Operating Advice

1. If the current scenario is unclear, first confirm whether `config_sim.yaml` or `config.yaml` is being used.
2. If script parameters are unclear, run `bash scripts/<script>.sh --help` first.
3. After modifying LCM messages, regenerate types with `bash scripts/generate_lcm_types.sh`.

## Safety Note

Do not mix simulation and hardware configurations. In particular, `simulation.enable_mujoco`, `motor_communication.type`, `spi_type`, IMU ports, and LCM channels must match the runtime scenario.
