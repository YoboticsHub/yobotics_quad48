# 4.4 SDK State Reading Workflow

## Purpose

This section explains how to read robot state through the SDK for upper-computer display, business logic, and joint debugging.

## Prerequisites

- The controller is running.
- The SDK has been built.
- The `QUAD_ROBOT_STATE` channel matches controller configuration.

## Example Program

State-reading example source:

```text
yobotics_sdk/example/robot_state_client.cpp
```

Built program:

```text
yobotics_sdk/build/yobot_robot_state_client
```

## Run

```bash
cd yobotics_sdk/build
./yobot_robot_state_client
```

Specify an LCM URL:

```bash
export YOBOTICS_LCM_URL="udpm://239.255.76.67:7667?ttl=255"
./yobot_robot_state_client
```

## Readable State

| State | Purpose |
| --- | --- |
| Current control mode | Determine whether the robot is in DAMP, RECOVERY, RL, or DEVELOPMENT |
| Velocity and attitude | Upper-computer display and motion-state evaluation |
| Control feedback | Confirm whether SDK commands are received by the controller |
| Joint-state channel | Debug low-level joint position, velocity, and torque |

## Success Criteria

- The program continuously outputs state.
- Mode, velocity, attitude, and other fields change with controller state.
- `QUAD_ROBOT_STATE` is visible in LCM monitoring.

## Troubleshooting

| Symptom | Action |
| --- | --- |
| No output | Check whether the controller is running and whether the LCM URL matches |
| State frequency is very low | Check network and CPU load |
| Field values do not change | Check whether the correct channel is subscribed |
