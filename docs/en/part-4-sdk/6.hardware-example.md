# 4.6 SDK Hardware Example

## Purpose

This section explains how to control a real robot with the SDK.

## Prerequisites

- The hardware controller has been started with `bash scripts/run_robot_controller.sh --config config.yaml`.
- The robot is in a safe posture, such as passive or damping.
- The SDK machine and robot side are network-reachable.
- SDK and controller use the same LCM URL.
- Velocity limits, safety checks, and emergency stop have been confirmed.

## Steps

### 1. Start the Controller on the Robot Side

```bash
# SSH to the robot, for example 192.168.1.100
ssh cat@robot_ip
```

```bash
bash scripts/run_robot_controller.sh --config config.yaml
```

### 2. Set LCM URL on the SDK Side

```bash
export YOBOTICS_LCM_URL="udpm://239.255.76.67:7667?ttl=255"
```

### 3. Read State

```bash
cd yobotics_sdk/build
./yobot_robot_state_client
```

### 4. Send Small Motion Commands

```bash
cd yobotics_sdk/build
./yobot_sport_client
```

![](image/res_2.png)

Recommended sequence: DAMP -> RECOVERY_STAND -> RL_WALK -> STAND_DOWN. Start with low speed and short-duration commands.

## Success Criteria

- State reading is stable.
- Controller logs show no LCM, SPI, or IMU errors.
- The robot responds to small commands and can stop or enter damping / passive at any time.

## Safety Note

Do not let SDK, WebRTC, remote controller, and external algorithms send conflicting commands at the same time during hardware tests. Stop commands immediately and use emergency stop if abnormal motion appears.
