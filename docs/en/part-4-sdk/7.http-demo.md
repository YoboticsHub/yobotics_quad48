# 4.7 SDK HTTP Control Service

## Purpose

This section explains the purpose and basic usage of the SDK HTTP example service. The service is suitable for upper computers, Web systems, or integration tests that send control commands indirectly through HTTP.

## Prerequisites

- The SDK has been built.
- The controller is running and can receive SDK commands through LCM.
- HTTP service and controller use the same LCM URL.

## Start the Service

```bash
cd yobotics_sdk/build
./yobot_http_server
```

To specify an LCM URL:

```bash
export YOBOTICS_LCM_URL="udpm://239.255.76.67:7667?ttl=255"
./yobot_http_server
```

## Common API Examples

Query status:

```bash
curl -X GET "http://192.168.1.100:8080/control/status" -H "Authorization: Bearer E15_Robot_Secure_Token_123"
```

Enter damping mode:

```bash
curl -X POST "http://192.168.1.100:8080/control/motion" -H "Authorization: Bearer E15_Robot_Secure_Token_123" -H "Content-Type: application/json" -d "{"mode":"damp"}"
```

Stop motion:

```bash
curl -X POST "http://192.168.1.100:8080/control/stop" -H "Authorization: Bearer E15_Robot_Secure_Token_123"
```

## Success Criteria

- The HTTP service listens on the configured port.
- Status query returns robot state.
- Control requests appear as corresponding LCM control messages in monitoring.

## Safety Note

HTTP token, listen address, and port should be changed according to site network-security requirements. Do not expose the control service to untrusted networks.
