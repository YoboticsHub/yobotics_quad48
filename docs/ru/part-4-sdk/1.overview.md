# 4.1 Каталог SDK и функции

## Назначение

SDK поддерживает высокоуровневую вторичную разработку. Он инкапсулирует низкоуровневую связь LCM, чтобы пользователи могли через C++-примеры выполнять управление движением, чтение состояния и интеграцию HTTP-сервиса управления.

## Каталоги кода

| Путь | Назначение |
| --- | --- |
| `yobotics_sdk/include/` | Заголовки SDK, типы LCM, обертки каналов, интерфейсы робота |
| `yobotics_sdk/example/` | Примеры управления движением, чтения состояния и HTTP-сервиса |
| `yobotics_sdk/tools/` | Инструменты упаковки SDK, развертывания на плате, версии и кросс-сборки |
| `yobotics_sdk/CMakeLists.txt` | Точка входа сборки SDK |
| `yobotics_sdk/SDK_User_Guide.md` | Английское руководство по использованию SDK |

При наличии противоречий это руководство имеет приоритет над исходными примечаниями пакета.

## Возможности SDK

- Инкапсулирует логику публикации и подписки LCM.
- Публикует высокоуровневые команды движения в `QUAD_ROBOT_CONTROL`.
- Читает состояние робота из `QUAD_ROBOT_STATE`.
- Поддерживает зеркальные каналы состояния и команд суставов.
- Предоставляет пример HTTP-сервиса для верхних компьютеров или Web-систем.

## Общие каналы

| Канал | Назначение |
| --- | --- |
| `QUAD_ROBOT_CONTROL` | Управляющая команда SDK |
| `QUAD_ROBOT_STATE` | Обратная связь состояния робота |
| `leg_control_data` | Состояние суставов |
| `leg_control_command` | Зеркало команд суставов |
| `Y15_development_state` | Состояние режима разработки |
| `Y15_development_command` | Команда режима разработки |

Префикс `Y15_` в каналах режима разработки исторический и не привязан к типу SPI-платы или модели робота. Аппаратная платформа E15 также использует эти каналы, если конфигурация не изменена.

## Предварительные условия

- Фреймворк управления использует управление через LCM.
- SDK и контроллер используют один и тот же URL LCM.
- Сеть разрешает UDP multicast.
- Поля контроллера `gamepad.lcm_control_channel` и `gamepad.lcm_state_channel` совпадают с каналами SDK.

## Примечание по безопасности

SDK отвечает только за связь и отправку команд. Он не определяет, находится ли робот в безопасной позе. Перед управлением физическим роботом проверьте состояние робота, ограничения скорости и возможность аварийной остановки.
