# 4.8 Использование демо SDK

## Назначение

Этот раздел кратко описывает порядок использования демо SDK, переменные окружения и типичные проблемы.

## Список демо

| Программа | Исходный файл | Назначение |
| --- | --- | --- |
| `yobot_sport_client` | `example/sport_client.cpp` | Отправка команд управления движением |
| `yobot_robot_state_client` | `example/robot_state_client.cpp` | Чтение состояния робота |
| `yobot_http_server` | `example/http_server.cpp` | Запуск HTTP-сервиса управления |

## Рекомендуемый порядок

1. Сначала запустите симуляцию или аппаратный контроллер.
2. Запустите `yobot_robot_state_client` и убедитесь, что состояние читается.
3. Запустите `yobot_sport_client` и отправьте малые управляющие команды.
4. Запускайте `yobot_http_server` только если нужна HTTP-интеграция.

## URL LCM

Работа на одной машине обычно работает со стандартным адресом LCM. Для развертывания на нескольких машинах задайте явно:

```bash
export YOBOTICS_LCM_URL="udpm://239.255.76.67:7667?ttl=255"
```

Контроллер, SDK, WebRTC и внешние алгоритмы должны использовать одну и ту же настройку.

## Устранение неполадок

| Симптом | Действие |
| --- | --- |
| После запуска демо нет состояния | Проверьте контроллер, URL LCM, firewall и multicast-маршрут |
| Управляющая команда не дает реакции | Убедитесь, что режим робота принимает управление SDK |
| Ошибка HTTP-токена | Проверьте заголовок запроса `Authorization` |
| Управление между машинами нестабильно | Сначала используйте `monitor_lcm.sh --no-gui`, чтобы проверить частоту канала |

## Примечание по безопасности

Демо SDK подходят для проверки цепочки. Не рекомендуется использовать их как необслуживаемые рабочие программы. Для полноценной интеграции добавьте подтверждение состояния, защиту по timeout, ограничения и логику аварийной остановки.
