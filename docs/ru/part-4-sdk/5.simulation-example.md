# 4.5 Пример SDK для симуляции

## Назначение

Этот раздел объясняет, как управлять симуляцией MuJoCo через SDK. Это хороший первый шаг проверки для высокоуровневой вторичной разработки.

## Предварительные условия

- Симуляция MuJoCo может запускаться.
- SDK собран.
- SDK, симулятор и контроллер используют один и тот же URL LCM.

## Шаги

### 1. Запуск симуляции в терминале 1

```bash
# Если MuJoCo установлен в Conda-окружении, сначала переключитесь из base в это окружение
conda env list
conda activate robot_controller
```

```bash
bash scripts/start_mujoco.sh --config config_sim.yaml
```

### 2. Мониторинг LCM в терминале 2

```bash
bash scripts/monitor_lcm.sh --no-gui
```

```bash
# Если LCM установлен в Conda-окружении, сначала переключитесь из base в это окружение
conda env list
conda activate robot_controller
```

### 3. Запуск управления движением SDK в терминале 3

```bash
cd yobotics_sdk/build
./yobot_sport_client
```

### 4. Запуск чтения состояния SDK в терминале 4

```bash
cd yobotics_sdk/build
./yobot_robot_state_client
```

## Критерии успешного выполнения

- Робот в MuJoCo Viewer реагирует на команды SDK, например переходит из положения лежа/демпфирования к стоянию и ходьбе.
- `monitor_lcm.sh` показывает `QUAD_ROBOT_CONTROL` и `QUAD_ROBOT_STATE`.
- Вывод чтения состояния меняется вместе с управляющими командами.

## Устранение неполадок

| Симптом | Действие |
| --- | --- |
| Команды SDK не дают реакции | Убедитесь, что контроллер находится в режиме, принимающем высокоуровневые команды |
| Чтение состояния пустое | Убедитесь, что URL LCM и канал состояния совпадают |
| Симуляция падает | Уменьшите команды скорости и проверьте модель, PD-параметры и ограничения действий |

## Примечание по безопасности

Симуляция не повреждает оборудование, но аномальное движение в симуляции обычно указывает на проблему конфигурации или модели. Не пропускайте эту проблему и не переходите сразу к физическому роботу.
