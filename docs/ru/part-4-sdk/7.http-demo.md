# 4.7 HTTP-сервис управления SDK

## Назначение

Этот раздел объясняет назначение и базовое использование примера HTTP-сервиса SDK. Сервис подходит для верхних компьютеров, Web-систем или интеграционных тестов, которые отправляют управляющие команды косвенно через HTTP.

## Предварительные условия

- SDK собран.
- Контроллер запущен и может получать команды SDK через LCM.
- HTTP-сервис и контроллер используют один и тот же URL LCM.

## Запуск сервиса

```bash
cd yobotics_sdk/build
./yobot_http_server
```

Чтобы указать URL LCM:

```bash
export YOBOTICS_LCM_URL="udpm://239.255.76.67:7667?ttl=255"
./yobot_http_server
```

## Примеры распространенных API

Запрос состояния:

```bash
curl -X GET "http://192.168.1.100:8080/control/status" -H "Authorization: Bearer E15_Robot_Secure_Token_123"
```

Вход в режим демпфирования:

```bash
curl -X POST "http://192.168.1.100:8080/control/motion" -H "Authorization: Bearer E15_Robot_Secure_Token_123" -H "Content-Type: application/json" -d "{"mode":"damp"}"
```

Остановка движения:

```bash
curl -X POST "http://192.168.1.100:8080/control/stop" -H "Authorization: Bearer E15_Robot_Secure_Token_123"
```

## Критерии успешного выполнения

- HTTP-сервис слушает настроенный порт.
- Запрос состояния возвращает состояние робота.
- Управляющие запросы появляются в мониторинге как соответствующие управляющие сообщения LCM.

## Примечание по безопасности

HTTP-токен, адрес прослушивания и порт нужно изменять согласно требованиям сетевой безопасности площадки. Не открывайте сервис управления для недоверенных сетей.
