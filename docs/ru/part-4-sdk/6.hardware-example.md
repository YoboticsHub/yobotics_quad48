# 4.6 Пример SDK для физического робота

## Назначение

Этот раздел объясняет, как управлять реальным роботом через SDK.

## Предварительные условия

- Аппаратный контроллер запущен командой `bash scripts/run_robot_controller.sh --config config.yaml`.
- Робот находится в безопасной позе, например passive или damping.
- Машина SDK и сторона робота доступны по сети.
- SDK и контроллер используют один и тот же URL LCM.
- Ограничения скорости, проверки безопасности и аварийная остановка подтверждены.

## Шаги

### 1. Запуск контроллера на стороне робота

```bash
# SSH на робота, например 192.168.1.100
ssh cat@robot_ip
```

```bash
bash scripts/run_robot_controller.sh --config config.yaml
```

### 2. Задание URL LCM на стороне SDK

```bash
export YOBOTICS_LCM_URL="udpm://239.255.76.67:7667?ttl=255"
```

### 3. Чтение состояния

```bash
cd yobotics_sdk/build
./yobot_robot_state_client
```

### 4. Отправка малых команд движения

```bash
cd yobotics_sdk/build
./yobot_sport_client
```

![](image/res_2.png)

Рекомендуемая последовательность: DAMP -> RECOVERY_STAND -> RL_WALK -> STAND_DOWN. Начинайте с малой скорости и кратковременных команд.

## Критерии успешного выполнения

- Чтение состояния стабильно.
- Журналы контроллера не показывают ошибок LCM, SPI или IMU.
- Робот реагирует на малые команды и может остановиться или войти в damping / passive в любой момент.

## Примечание по безопасности

Во время аппаратных тестов не допускайте одновременной отправки конфликтующих команд из SDK, WebRTC, пульта и внешних алгоритмов. При появлении аномального движения немедленно остановите команды и используйте аварийную остановку.
