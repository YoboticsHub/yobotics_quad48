# 4.3 Процесс управления движением через SDK

## Назначение

Этот раздел объясняет, как отправлять высокоуровневые команды управления движением через SDK.

## Предварительные условия

- Контроллер работает в симуляции или на физическом роботе.
- SDK собран.
- SDK и контроллер используют один и тот же URL LCM.
- Робот находится в режиме, принимающем высокоуровневое управление, например `gamepad->device_type`: `hybrid` или `lcm`.

## Пример программы

Исходный файл примера управления движением:

```text
yobotics_sdk/example/sport_client.cpp
```

Собранная программа:

```text
yobotics_sdk/build/yobot_sport_client
```

## Запуск

```bash
cd yobotics_sdk/build
./yobot_sport_client
```

## Вывод при запуске


Чтобы указать URL LCM:

```bash
export YOBOTICS_LCM_URL="udpm://239.255.76.67:7667?ttl=255"
./yobot_sport_client
```

## Общие поля управления

| Поле / API | Назначение |
| --- | --- |
| `Move(vx, vy, vyaw)` | Задает продольную, боковую и yaw-скорость |
| `BodyHeight(h)` | Задает команду высоты корпуса |
| `Euler(roll, pitch)` | Задает команду ориентации корпуса |
| API `1000` | `PASSIVE` |
| API `1001` | `DAMP` |
| API `1002` | `RL_WALK` |
| API `1003` | `RL_RUN` |
| API `1005` | `DEVELOPMENT` |
| API `1006` | `RECOVERY_STAND` |
| API `1007` | `STAND_DOWN` |

Повторно используемая последовательность управления: PASSIVE -> DAMP -> STAND_DOWN -> RECOVERY_STAND ...

## Критерии успешного выполнения

- Контроллер получает `QUAD_ROBOT_CONTROL`.
- Канал обратной связи состояния показывает изменения режима и команд скорости.
- Робот в симуляции или физический робот реагирует на ограниченные команды скорости.

## Примечание по безопасности

При аппаратных тестах начинайте с малых скоростей, например малых `vx`, `vy` и `vyaw`. Не отправляйте большие скорости, быстрые переключения режимов или большие команды ориентации корпуса до проверки.
