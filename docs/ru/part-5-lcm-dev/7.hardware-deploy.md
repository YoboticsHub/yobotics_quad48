# 5.7 Развертывание собственных алгоритмов на роботе

## Назначение

Этот раздел объясняет переход от развертывания в симуляции к развертыванию собственных алгоритмов на физическом роботе. Цель аппаратного развертывания — не заставить алгоритм сразу работать, а наблюдаемым, останавливаемым и обратимым способом подтвердить, что логика симуляции сохраняется на реальном роботе.

Принцип по умолчанию: сначала симуляция, затем стойка или безопасная зона; начинайте с малой амплитуды и коротких тестов. При любой аномалии вернитесь в `DAMP` или остановите контроллер, затем вернитесь к отладке в симуляции. Не скрывайте проблемы увеличением PD, момента или ограничений.

## Предварительные условия

- Алгоритм проверен в MuJoCo.
- `monitor_lcm.sh` видит состояние и команды режима разработки.
- Алгоритм публикует команду отключения или безопасную команду при выходе.
- Аппаратный `config.yaml` проверен на модель робота, SPI, IMU, LCM и проверки безопасности.
- Аварийная остановка, стойка или безопасная зона готовы.
- Персонал на площадке знает, как вернуться в DAMP или остановить контроллер.

## Чек-лист перехода от симуляции к роботу

| Пункт | Требование |
| --- | --- |
| Согласованность конфигурации | Проверьте `robot_id`, имена каналов и параметры модели |
| Каналы LCM | `Y15_development_state` и `Y15_development_command` видны |
| SPI / IMU | У контроллера нет ошибок связи, данные ориентации без очевидных скачков |
| Поза робота | roll/pitch стабильны и ниже порога самопроверки режима разработки |
| Порядок суставов | Совпадает с 12-мерным порядком в `development_command_t` |
| Углы суставов по умолчанию | Соответствуют физической начальной позе |
| PD-параметры | Не превышают диапазон, проверенный в симуляции |
| Амплитуда действия | Для первого запуска используйте малую амплитуду и короткую длительность |
| Путь выхода | `Ctrl+C`, переключение DAMP и аварийная остановка подтверждены доступными |

## Шаги развертывания на роботе

1. Поместите каталог алгоритма, конфигурационный файл и файл модели в программный пакет на стороне робота.
2. Убедитесь, что URL LCM, `robot_id`, канал состояния и канал команд в конфигурации алгоритма совпадают с `config.yaml`.
3. Передайте пакет на робота и запустите аппаратный контроллер:

```bash
bash scripts/run_robot_controller.sh --config config.yaml
```

4. Прочитайте состояние и подтвердите стабильную позу робота.
5. Запустите мониторинг LCM:

```bash
bash scripts/monitor_lcm.sh --no-gui
```

6. Войдите в `DEVELOPMENT` через SDK или другую точку управления.
7. Сначала запустите `wave_algorithm` с уменьшенной амплитудой, чтобы подтвердить направление и логику выхода.
8. Затем запустите собственный алгоритм, например:

```bash
python3 external_algorithms/walk_algorithm/run_algorithm.py --config external_algorithms/walk_algorithm/config.yaml
```

9. Наблюдайте состояние через журналы и мониторинг LCM:

```bash
bash scripts/monitor_lcm.sh --no-gui
tail -f log/robot_log.txt
```

10. Первый запуск держите коротким. Активно выйдите после подтверждения стабильности состояния, команд и позы.

## Критерии успешного выполнения

- У аппаратного контроллера нет ошибок SPI, IMU, LCM или проверок безопасности.
- Внешний алгоритм получает реальное состояние робота.
- Робот выполняет только малые, стабильные и останавливаемые движения.
- После выхода алгоритма робот входит в безопасное состояние.

## Финальная проверка перед запуском на роботе

| Пункт | Требование |
| --- | --- |
| Амплитуда действия | Сначала используйте малую амплитуду и короткую длительность |
| Порядок суставов | Точно совпадает с `development_command_t` |
| PD-параметры | Не превышают диапазон, проверенный в симуляции |
| Частота | Не превышает того, что контроллер и LCM могут стабильно обработать |
| Проверки безопасности | Оставить включенными |
| Аварийная остановка | Может быть немедленно активирована на площадке |

## На что смотреть при мониторинге

| Пункт | Нормальное поведение |
| --- | --- |
| `Y15_development_state` | Обновляется непрерывно; `robot_id` равен Y15, если не настроено иначе |
| `Y15_development_command` | Обновляется непрерывно во время работы и отправляет `enable_development_mode` = 0 при выходе |
| Журналы контроллера | Нет ошибок SPI, IMU, LCM или проверок безопасности |
| roll/pitch | Стабильная поза; самопроверка проходит после выхода из внешнего захвата |
| Цели суставов | Непрерывные, без NaN/Inf и очевидных скачков |
| Фактические суставы | Следуют целям без аномальной тряски, шума или насыщения |

`robot_id` должен совпадать с конфигурацией контроллера. Примеры конфигураций часто используют `"Y15"`; это независимо от физической модели.

## Обработка нештатных ситуаций

| Аномалия | Действие |
| --- | --- |
| Поза быстро меняется | Немедленно остановите алгоритм и переключитесь в DAMP или аварийную остановку |
| Направление сустава неверное | Остановите аппаратное тестирование и проверьте порядок сустав за суставом в симуляции |
| Потеря команды или timeout | Проверьте частоту LCM, сеть и поток отправки |
| Самопроверка не проходит | Проверьте IMU, позу на стойке и журналы контроллера |
| NaN/Inf или ошибка размерности | Остановите развертывание и отладьте вход модели |
| Тряска или необычный звук | Уменьшите амплитуду и PD; вернитесь в симуляцию и не продолжайте аппаратную настройку |

## Примечание по безопасности

Если физическое движение отличается от симуляции, немедленно остановитесь и вернитесь к отладке в симуляции. Не увеличивайте PD, момент или ограничения скорости, чтобы скрыть проблемы модели, оценки состояния или порядка суставов.
