# 5.1 Структура LCM

## Назначение

Этот раздел объясняет структуру связи LCM во фреймворке управления, чтобы пользователи понимали поток данных между SDK, MuJoCo, контроллером и внешними алгоритмами.

## Что такое LCM

LCM — это механизм связи, используемый фреймворком управления для передачи сообщений между процессами и машинами. Контроллер, MuJoCo, SDK, WebRTC и внешние алгоритмы публикуют и получают LCM-сообщения для управляющих команд, обратной связи состояния, обмена данными суставов симуляции и интеграции алгоритмов режима разработки.

Имя LCM-канала похоже на topic сообщения, например `QUAD_ROBOT_CONTROL` или `leg_control_data`. Поля и типы сообщений определяются файлами `.lcm` в `lcm-types/`. Участники связи должны использовать совпадающие имена каналов и типы сообщений.

## Схема связи

```text
SDK / HTTP / WebRTC
        |
        | QUAD_ROBOT_CONTROL / QUAD_ROBOT_STATE
        v
YBT_Controller
        |
        +-- leg_control_command / leg_control_data
        |       |
        |       +-- MuJoCo simulation or hardware communication
        |
        +-- Y15_development_command / Y15_development_state
                |
                +-- external_algorithms Python development package
```

## Основные каналы

| Канал | Направление | Назначение |
| --- | --- | --- |
| `QUAD_ROBOT_CONTROL` | SDK / WebRTC -> контроллер | Высокоуровневое управление движением |
| `QUAD_ROBOT_STATE` | контроллер -> SDK / WebRTC | Высокоуровневая обратная связь состояния |
| `leg_control_data` | симуляция / физический робот -> контроллер | Состояние суставов |
| `leg_control_command` | контроллер -> симуляция / физический робот | Команда суставов |
| `Y15_development_state` | контроллер -> внешние алгоритмы | Состояние режима разработки |
| `Y15_development_command` | внешние алгоритмы -> контроллер | Команда суставов режима разработки |

Примечания:

1. `Y15_development_*` — исторический префикс каналов, он не ограничен роботами Y15.
2. Режим разработки аппаратных платформ E15 и Y15 использует эти каналы, если конфигурация не изменена.
3. При изменении имен каналов контроллер, `config.yaml` внешнего алгоритма и `robot_id` нужно менять вместе.

## Рекомендации по эксплуатации

1. Перед изменением имен каналов убедитесь, что все точки связи обновляются вместе.
2. Если данные отсутствуют, сначала выполните `bash scripts/monitor_lcm.sh --no-gui`, чтобы проверить существование канала.
3. После изменения файлов `.lcm` выполните `bash scripts/generate_lcm_types.sh`.
4. При развертывании на нескольких машинах держите URL LCM, сетевой интерфейс и multicast-маршруты согласованными.

## Примечание по безопасности

LCM — это связь сообщениями без установления соединения. Если имена каналов или типы сообщений у publisher и subscriber различаются, система не исправит несоответствие автоматически. Симптомами могут быть отсутствие реакции, отсутствие состояния или устаревшие управляющие команды.
