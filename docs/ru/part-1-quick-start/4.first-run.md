# 1.4 Первый запуск

## Назначение

Этот раздел задает рекомендуемую последовательность первого использования пакета и помогает не переходить сразу к физическому роботу, что усложняет диагностику и повышает риски безопасности.

## Предварительные условия

- Вы находитесь в корневом каталоге проекта.
- Conda установлена или доступна другая среда выполнения Python.
- Текущая машина имеет доступ к `scripts/`, `config_sim.yaml` и `resources/` в пакете.

## Шаги

### 1. Подготовка окружения

```bash
bash scripts/setup_conda_env.sh
conda activate robot_controller
```

### 2. Запуск симуляции MuJoCo

```bash
bash scripts/start_mujoco.sh --config config_sim.yaml
```

### 3. Проверка связи LCM в другом терминале

```bash
conda activate robot_controller
bash scripts/monitor_lcm.sh --no-gui
```

### 4. Сборка и запуск примеров SDK

```bash
cd yobotics_sdk
mkdir -p build
cd build
cmake ..
make -j4
./yobot_sport_client
```

После запуска `./yobot_sport_client` поведение описано в разделе 4.3.

### 5. Проверка перед работой с физическим роботом

Перед переключением на реального робота проверьте:

- `simulation.enable_mujoco: false` in `config.yaml`.
- `motor_communication.type`, `spi_type`, SPI-устройства и порт IMU заданы корректно.
- Аварийная остановка, источник питания, аккумулятор, поверхность и безопасная зона проверены.
- Любая новая модель или алгоритм прошли проверку в симуляции.

## Критерии успешного выполнения

- Симулятор MuJoCo и контроллер продолжают работать.
- Мониторинг LCM показывает каналы и частоту сообщений.
- Примеры SDK могут отправлять управляющие команды или читать состояние, а робот в симуляции реагирует соответственно.
- Журналы контроллера не показывают отсутствующих ресурсов, отсутствующих библиотек, ошибок импорта Python или ошибок инициализации связи.

## Примечание по безопасности

Во время первого запуска не изменяйте ограничения скорости, ограничения момента, PD-параметры или переключатели проверок безопасности. Когда путь по умолчанию стабилен, изменяйте параметры по одному.
