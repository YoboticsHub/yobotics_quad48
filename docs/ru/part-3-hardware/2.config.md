# 3.2 Изменение config.yaml

## Назначение

Этот раздел объясняет параметры `config.yaml`, которые нужно проверить и изменить перед работой с физическим роботом, особенно SPI-конфигурацию Y15/E15 и конфигурацию чтения IMU.

## Предварительные условия

- Текущая цель — реальный робот.
- Проверка в симуляции MuJoCo завершена.
- Известны модель робота на площадке, архитектура системы, SPI-устройства и тип IMU.

## Основная конфигурация

### Переключатель симуляции

```yaml
simulation:
  enable_mujoco: false
```

При работе с физическим роботом MuJoCo должен быть отключен. Симуляция использует `config_sim.yaml` и LCM; физический робот использует `config.yaml` и читает состояние моторов из реальных SPI-устройств.

### Связь с моторами

Пример аппаратной конфигурации в корне проекта:

```yaml
motor_communication:
  type: "spi_legacy"
  spi_type: "E15"
  spi_device0: "/dev/spidev3.0"
  spi_device1: "/dev/spidev4.0"
```

`motor_communication.type` выбирает реализацию связи с моторами. `spi_type` может быть только `E15` или `Y15` и проверяется `FSM_ConfigLoader`. Он влияет на скорость SPI, raw-структуру данных, направление суставов и нулевые смещения. Это не тип IMU и он не выбирает драйвер IMU автоматически.

#### Настройка номера SPI-устройства

Сначала подтвердите фактические узлы устройств на целевом роботе:

```bash
ls -l /dev/spidev*
```

Затем запишите два существующих узла в `spi_device0` и `spi_device1`, а по журналам запуска контроллера подтвердите сопоставление board0/board1.

#### Различия SPI между Y15 и E15

При переключении на Y15 как минимум проверьте:

```yaml
motor_communication:
  type: "spi_legacy"
  spi_type: "Y15"
  spi_device0: "/dev/site_confirmed_device0"
  spi_device1: "/dev/site_confirmed_device1"
```

### IMU

Y15 и E15 используют разных производителей IMU, потому что аппаратные платформы используют разные датчики: Y15 использует MicroStrain, а E15 использует HipNuc. Программа читает их через драйверы Lord и HipNuc соответственно.

Конфигурация IMU независима от `spi_type` Y15/E15:

| Типичная комбинация | Конфигурация IMU | Пример порта |
| --- | --- | --- |
| E15 + HipNuc | hipnuc | /dev/ttyS0 |
| Y15 + MicroStrain | lord | port_base=/dev/ttyUSB, port_number=0 |

Рекомендуемые поля:

```yaml
imu:
  type: "hipnuc"
  port_base: "/dev/ttyS0"
  port_number: 0
  baud_rate: 460800
```

Не смешивайте три стиля драйверов. HipNuc использует полный путь; Lord обычно использует префикс устройства плюс `port_number`.

Подтвердите фактические порты по списку устройств:

```bash
ls -l /dev/ttyS* /dev/ttyUSB* /dev/ttyACM*
```

Не задавайте `port_base` как полный порт и одновременно `port_number` так, чтобы путь дублировался.

### LCM и удаленное управление

```yaml
gamepad:
  device_type: "hybrid"
  lcm_control_channel: "QUAD_ROBOT_CONTROL"
  lcm_state_channel: "QUAD_ROBOT_STATE"
```

SDK, WebRTC и контроллер должны использовать один и тот же URL LCM, канал управления и канал состояния.

### Проверки безопасности

```yaml
safety_checker:
  enable_safety_check: true
```

Не отключайте проверки безопасности на реальном роботе. Не увеличивайте ограничения ориентации, скорости, момента или положения без проверки.

## Чек-лист конфигурации

1. Подтвердите `simulation.enable_mujoco: false`.
2. Подтвердите, что `motor_communication.type` соответствует целевой SPI-реализации.
3. Подтвердите, что `spi_type` соответствует реальной плате связи.
4. Используйте `ls -l /dev/spidev*`, чтобы подтвердить наличие обоих SPI-узлов.
5. Подтвердите, что тип IMU, порт, номер порта и baud rate соответствуют драйверу.
6. Запустите контроллер и проверьте журналы инициализации SPI/IMU.
7. Наблюдайте состояние суставов, ориентацию, угловую скорость и состояние проверок безопасности.
8. При любой аномалии сначала остановитесь и вернитесь к проверке конфигурации, устройств и симуляции.

## Критерии успешного выполнения

- `config.yaml` явно является аппаратной конфигурацией.
- Тип SPI и оба узла устройств соответствуют оборудованию площадки.
- Тип IMU, порт и baud rate соответствуют оборудованию площадки.
- Каналы SDK / WebRTC / внешних алгоритмов совпадают с контроллером.
- Журналы контроллера показывают корректный тип SPI, сопоставление устройств и инициализацию IMU.
- Углы суставов, угловая скорость, ориентация и timestamp IMU обновляются непрерывно.
- Проверки безопасности остаются включенными.

## Устранение неполадок

| Симптом | Типичная причина | Действие |
| --- | --- | --- |
| SPI не открывается | Неверное имя устройства или проблема прав доступа | Проверьте `/dev/spidev*` и права пользователя |
| Недопустимый `spi_type` | Опечатка или неподдерживаемое имя модели | Используйте только `E15` или `Y15` |
| SPI открывается, но направление суставов аномальное | Неверный тип SPI, порядок узлов, смещения или сопоставление суставов | Остановитесь и проверьте `spi_type`, оба узла и нулевые точки |
| IMU не открывается | Неверный тип, serial-порт, номер порта или baud rate | Проверьте `imu.type`, `port_base`, `port_number`, `baud_rate` и `/dev/tty*` |
| Данные IMU не меняются | Проблема serial-конфигурации, старый драйвер или отключенный датчик | Проверьте журналы потери IMU от проверок безопасности |
| Кватернион/ориентация аномальны | Несовпадение типа IMU или порядка данных драйвера | Проверьте тип драйвера, журналы запуска и вывод ориентации |
| Дублированный путь порта | `port_base` уже является полным путем, а к нему добавляется номер | Используйте полный путь для HipNuc; префикс плюс номер для Lord/AHRS |
| Робот аномально трясется | Неверная модель, порядок суставов или PD-параметры | Немедленно остановитесь и вернитесь к проверке в симуляции |
