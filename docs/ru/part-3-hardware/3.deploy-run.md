# 3.3 Развертывание и запуск физического робота

## Назначение

Этот раздел объясняет, как передать пакет развертывания на сторону робота и запустить физический контроллер.

## Предварительные условия

- Проверка в симуляции завершена.
- `config.yaml` проверен для физического робота.
- Аккумулятор, аварийная остановка, кабели, поверхность и безопасная зона проверены.
- Сеть на стороне робота доступна.

## Развертывание программы

Передайте программу на робота. Параметры скриптов и целевые адреса зависят от конфигурации площадки. После передачи убедитесь, что контроллер, библиотеки, конфигурация, модели и ресурсы присутствуют полностью.

```bash
# 1. Войти по SSH, например:
ssh username@robot_ip

# 2. Передать скомпилированный файл
scp local_file username@robot_ip:/remote/target/path/

# 3. Передать каталог
scp -r local_folder username@robot_ip:/remote/target/path/
```

## Запуск аппаратного контроллера

Запускайте из корня проекта на стороне робота:

```bash
bash scripts/run_robot_controller.sh --config config.yaml
```

Скрипт выбирает пути по результату `uname -m`:

| Архитектура | Каталог контроллера | Каталог библиотек |
| --- | --- | --- |
| `x86_64` | `bin/ybt_ctrl` | `lib/` |
| `aarch64` / `arm64` | `bin_rk3588/ybt_ctrl` | `lib_rk3588/` |

## Последовательность выполнения

1. После запуска контроллера держите робота в безопасном режиме.
2. Убедитесь, что в журналах нет ошибок SPI, IMU, библиотек или конфигурации.
3. Войдите в `RECOVERY_STAND` через пульт, SDK или верхний компьютер.
4. Когда поза стабилизируется, переходите в режимы движения, например `RL_WALK`.
5. Для тестирования внешних алгоритмов сначала войдите в `DEVELOPMENT`.

## Критерии успешного выполнения

- Контроллер запускается и продолжает работать.
- Вывод терминала показывает корректные пути конфигурации, исполняемого файла и библиотек.
- Не возникает ошибок инициализации SPI, IMU или LCM.
- Робот может войти в безопасную позу, а состояние LCM можно мониторить.

## Примечание по безопасности

Сейчас `run_robot_controller.sh` настраивает multicast-маршрутизацию LCM для `eth1`. Если сетевой интерфейс площадки отличается, сначала настройте multicast-конфигурацию. При аномальной позе, необычном звуке, потере управления, подергиваниях или непрерывных ошибках журнала немедленно остановитесь.
